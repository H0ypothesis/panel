# Panel

基于 Pi 的非线性 Agent 工作台。对话是一张图，每轮对话是一个节点；从任意已完成的节点继续，只继承该节点到根的路径，可以让多个方向同时运行。真实模型支持读取网页与搜索资料、下载和处理文件、编写和修改代码、执行命令。未选择本地项目时，文件保存在各空间独立的临时目录。工具按所选模式请求人工批准或由独立安全模型审核。

产品定义、边界和验收标准见 [PRD](docs/PRD.md)。

macOS 客户端使用原生窗口并内置运行时，可直接打开 `Panel.app`。构建、模型配置和数据位置见 [macOS 客户端说明](docs/MACOS.md)。

## 启动

需要 Node.js ≥ 22.19。`pi/` 以 Git 子模块固定到已验证的上游版本，克隆时一并拉取：

```bash
git clone --recurse-submodules https://github.com/H0ypothesis/panel.git
cd panel
npm ci --ignore-scripts
npm run setup:pi
npm run dev
```

如果已克隆但没有初始化子模块，先运行 `git submodule update --init --recursive`。依赖升级或修改依赖时使用 `npm install --ignore-scripts`。

打开 <http://127.0.0.1:4317>。`setup:pi` 使用 Pi 自带生成器下载模型元数据，首次运行或升级 Pi 后执行一次；随后启动和演示模式可离线使用。

安装入口兼容 models.dev 将 `kimi-for-coding` 拆分为区域目录的变化：把与当前 Pi `api.kimi.com` 端点对应的 `kimi-code-plan-cn` 映射回生成器使用的名称。仍保留 `--strict --data-only` 校验；网络失败或供应商目录确实缺失时会报错。遇到 `Cannot hydrate missing providers: kimi-coding` 时，更新 Panel 后重新运行 `npm run setup:pi`。

没有 API Key 也可体验对话分支工作流。默认提供 **Pi Demo 演示模型**和明确标注的示例探索。演示模型使用真实 Pi Agent 和 faux provider 流式执行预设回复，不是远程模型推理，不产生模型费用，也不会执行本地或联网工具。

## 真实模型

复制 `.env.example` 为 `.env`，填写所需供应商，再重启服务：

```dotenv
ANTHROPIC_API_KEY=...
OPENAI_API_KEY=...
GEMINI_API_KEY=...
```

无需填写全部供应商。模型目录与支持的思考等级取自 Pi。界面左下角「模型连接」显示配置状态，对话输入框下方可以单独选择执行模型与思考强度。环境变量已存在时优先使用环境变量。

也支持 Paperbypass 网关。在 `.env` 中配置后重启，Luna Pro 会出现在模型列表中：

```dotenv
PAPERBYPASS_API_KEY=你的密钥
PAPERBYPASS_BASE_URL=https://aigateway.paperbypass.com/api
PAPERBYPASS_MODEL=openai/gpt-5.6-luna-pro
PANEL_DEFAULT_MODEL=paperbypass/openai/gpt-5.6-luna-pro
```

网关通过 `Authorization: Bearer` 调用 `/api/v1/messages`，支持流式文本对话。`PANEL_DEFAULT_MODEL` 决定从探索起点发起对话时的默认模型；历史对话仍继承各自的模型设置。当前网关配置不发送额外思考参数，采用 128,000 的本地上下文预算与 8,192 的输出上限，不提供网关费用估算。

首版支持 API Key/Anthropic token 环境变量；不会读取 Pi CLI 的 OAuth 登录状态。模型密钥只在服务端使用，不保存在浏览器或导出文件中。

Atria 使用 [官方文档](https://api.atria-asi.ai/docs) 的 Messages 接口，在 `.env` 中添加：

```dotenv
ATRIA_API_KEY=你的密钥
ATRIA_BASE_URL=https://api.atria-asi.ai
ATRIA_MODEL=Atria-Dawn-Preview
```

重启后可在模型选择器中选择 `Atria-Dawn-Preview`。该接口通过 `x-api-key` 调用 `/v1/messages`，支持流式文本对话，上下文窗口为 256,000 tokens。Panel 采用 8,192 tokens 的本地输出预算，不发送额外思考参数，不提供 Atria 费用估算。如需设为默认模型，将 `PANEL_DEFAULT_MODEL` 改为 `atria/Atria-Dawn-Preview`。

## 使用

- 导入他人的探索：在「新建探索 → 导入 JSON」选择 Panel 导出的 JSON 文件，或填写服务所在机器上的绝对路径 / `~/` 路径（最大 100 MiB）。导入后自动打开独立探索，可查看原有分支、问题、回答和工具记录，并从有效的已完成节点继续分支。每次导入生成新的空间和节点 ID，不覆盖已有探索；无需配置原作者使用的模型即可阅读结果。源工作目录、本地项目文件、Git 恢复快照、执行授权和压缩缓存不会恢复，审批模式重置为「请求批准」，导出时尚未结束的任务与审批标记中断，不会自动运行。

- 新建探索：填写主题和可选背景，得到根节点，默认使用空间临时目录；点击根节点卡片的「临时目录」，或在根节点详情中查看空间 ID、完整路径及选择本地项目。
- 对话输入框下方选择执行模型与思考强度；卡片、详情及选择器中的模型名称旁统一以 K/M 显示上下文窗口容量。审批模式和独立安全模型位于顶部可收起的主题区，收起和展开时所选值保持不变。
- 左侧栏支持平滑收起和展开；窄屏以抽屉形式打开，系统启用减少动画时取消过渡。
- 顶部可选择浅色、深色或跟随系统主题，默认跟随系统并实时自动切换；手动选择会保存在当前浏览器，刷新后保留。
- 悬停或用键盘聚焦卡片右侧连接点时，连接点展开为圆形 `+`；点击后在画布打开临时草稿卡片，以虚线连接来源。可直接输入问题、上传附件、选择显示容量的执行模型和思考深度，再点击「生成」；`⌘/Ctrl Enter` 提交，普通 Enter 换行。根节点及已完成且上下文有效的节点可创建分支，触屏上加号常显；右侧输入区仍可使用。
- 画布草稿继承来源节点配置；来源正被选中时使用当前输入区设置。取消不会创建正式节点；请求失败保留文字、附件和配置，同一请求可重试而不会重复创建。切换来源或探索时，未取消的草稿暂存在前端内存，每个探索一次展示一个，刷新后不保留。若来源路径失效或节点版本变化，需重新打开草稿确认后再提交。
- 每张卡片保留上下文圆环，按最近一次调用的输入（含缓存）加该次生成占窗口的比例计算；悬停查看计数来源、窗口和原文档案大小。旁边以 `49K / 1.8K` 显示该卡片任务累计输入与输出，左侧输入、右侧输出；悬停查看含义、精确 token 计数及多次调用累计的统计口径。
- 在「上下文路径」查看原始父链档案、本轮实际请求与摘要，以及为下一轮准备的摘要。画布高亮当前父链；原文估算与压缩后的实际输入估算分别显示。
- 生成时可以选择其他节点继续提问，同一空间也可并行探索。默认不限制全局运行节点数量；模型思考、联网查询和审批不占用文件锁，文件工具仅在访问冲突文件时等待。
- 失败或已停止的卡片及详情提供「原地重试」：恢复本轮 Git 快照记录的文件修改，再沿用原问题、附件、模型配置和执行目录，在同一卡片重新运行。后续手动或其他分支修改冲突时提示原因并停止，不覆盖文件。
- 非根节点卡片支持「编辑指令」：弹窗预填当前问题、执行模型和思考强度，确认后在原节点重新生成，保留节点 ID 和画布位置。新运行保留原附件并继承父路径，不混入旧的本轮回答或工具结果。
- 编辑后保留已有后代，并标记为「上下文已过期」；这些节点仍可查看，需沿父到子的顺序重新生成后才能继续分支。目标节点或其后代有运行、排队任务时，先停止这些任务再编辑或删除。
- 非根节点卡片支持「删除」：确认弹窗显示目标问题和后代数量，确认后删除目标及整棵后代子树，兄弟分支保留；根节点不可删除。普通编辑重新生成和删除不会回滚已发生的文件修改或命令效果。
- 取消只影响当前节点；未完成的节点不能作为后续上下文，需要从父节点继续。
- 搜索：`⌘/Ctrl K`；聚焦输入：`B`；发送：`⌘/Ctrl Enter`。
- 在对话阅读区向上滚动时，分支输入区会自动收起；点击底部入口或按 `B` 可展开并继续输入，草稿和模型选择会保留，也可点击输入区标题手动收起。
- 拖拽节点、缩放、自动布局和适配画布可用于整理结构。画布左上角默认展示全局缩略视图，显示全部节点和当前视野；颜色始终表示分支，运行中卡片增加同色柔光高亮和动态虚线边框，已完成卡片保持静态，底部图例说明状态。点击定位、拖动平移、滚轮缩放，底部工具栏可切换显示；减少动态效果模式下保留静态虚线区分。
- 自动布局按钮在左下角工具栏。右上角「Git 记录」默认折叠，点击标题可展开或收起，点击更新记录会定位对应的操作卡片。
- 导出菜单支持完整探索 JSON（含原始模型消息、引用快照与附件原件）和选中路径 Markdown（含引用来源及正文、附件清单）。

## 引用其他卡片

在画布草稿卡片、右侧输入框或编辑指令弹窗中输入 `@`，可搜索当前探索内已完成且上下文有效的卡片；继续输入按问题或回答筛选。点击候选，或用 `↑` / `↓` 切换、`Enter` 选择，`Esc` 关闭候选框。`⌘/Ctrl Enter` 仍用于发送。选中后插入问题摘要，并在输入框下方显示引用标签，发送前可逐个移除；实际引用以标签为准，单独输入普通 `@` 文字不会引用卡片。每轮最多选择 **20 张卡片**，不能跨探索选择。

发送时只把所选卡片的**问题和回答**加入本轮上下文，并保存当时的来源版本与内容快照。引用不带入来源卡片的祖先、工具记录、附件或其他引用，也不改变父链和画布连线。后续从当前卡片继续分支时，引用资料随本轮消息继承；其他未选分支不会自动进入上下文。

节点详情和上下文页可展开查看引用快照，并定位仍存在的来源卡片。来源之后被重新生成或删除，已提交引用仍保留原内容；原地重试及未修改引用的编辑重新生成沿用已保存快照。引用资料不会新增工具操作授权，仍遵循现有审批设置。

「新分支重试」会预填原问题及引用选择，创建新节点时重新获取所选来源的当前内容。若来源已删除、尚未完成或上下文失效，先移除不可用引用再提交；原卡片的快照仍保留。

引用随节点保存，刷新和服务重启后保留；发送失败时保留草稿选择。JSON 导出导入保留当前及历史运行的快照，导入时重映射现存来源，已删除来源保留独立历史标识；Markdown 导出包含来源与快照正文。

## 对话附件

右侧对话输入框和画布上的草稿卡片均可点击附件按钮或拖入多个文件。发送前查看文件名、类型和大小，图片显示缩略预览，点击移除按钮可取消单个附件。只上传文件也能发送，默认问题为「请分析上传的附件。」。未发送的附件属于浏览器草稿，刷新后不保留；发送失败时保留草稿，可继续重试。

每轮最多 **5 个文件**，单个最大 **10 MiB**，合计最大 **20 MiB**。支持 UTF-8 文本与代码文件（如 TXT、Markdown、CSV、JSON）、PDF 和 PNG/JPEG/WebP 图片。每份文本与代码最多发送前 100,000 个字符，PDF 最多提取前 100 页及 100,000 个字符，超出会标记为部分内容，原件仍完整保存。PDF 在本机解析且不提供 OCR；扫描 PDF、Office 文档和其他未支持格式需先转换。图片通过原生图像消息提交，需要支持图像输入的真实模型。演示模型可体验上传和保存流程，回答仍为预设内容。

附件随节点保存，并只沿该节点的父链继承，兄弟分支不会收到它。刷新或重启后可在节点详情查看并下载原件；编辑后重新生成和原地重试都会保留附件，旧运行也保留对应原件。上传不会运行文件或覆盖项目中的同名文件。

附件原件与提取内容保存在本地数据目录中；JSON 导出包含原件，导入会恢复附件关系，Markdown 导出只列出文件信息。导入 JSON 最大 100 MiB，大量附件或多个运行版本可能使导出超过此限制。删除节点及子树或探索时，对应记录内的附件和旧运行副本一并移除。

## 上下文压缩

在右侧「上下文路径」中管理压缩。自动压缩默认开启，开关对后续任务生效；服务在每次模型请求前检查这条路径的容量，包括长任务中工具结果追加后的下一轮请求。达到预算时，将早期历史整理为摘要，保留根背景、当前问题和近期完整消息，工具调用与结果不会拆开。压缩会额外调用当前执行模型，状态与用量可查看。

**每条分支独立判断是否压缩。** A 分支压缩后，尚未达到阈值的 B 分支继续使用完整父链原文；共同祖先已有摘要也不会自动让 B 改用摘要。摘要绑定来源节点的运行版本与内容，祖先重新生成或内容变更后，旧摘要不能继续套用。

已完成且上下文有效的非根节点可点击「压缩当前路径」，使用当前所选真实模型生成摘要，成功后在画布新增一个圆形压缩节点。点圆点的「+」会使用对应摘要，点它前面原卡片的「+」会保留完整原文；两种选择分别沿后代继承，互不影响。原文路径超出可用预算时会明确停止。压缩后的第一张对话卡片左侧用棕褐色加粗标记，后续卡片不重复标记。再次压缩会保留之前的圆点和关联分支。生成过程可以停止，其他分支可以继续运行；演示模型不能生成真实摘要。

卡片不再显示压缩状态文字或「上下文 / 窗口」数值。上下文圆环包含最近一次调用的输入及该次生成，生成期间更新估算，收到供应商计数后校准；任务累计输入与输出以数字对单独展示，不加「本轮」「输入」「输出」标签，含义和精确计数放在悬浮说明中。详细计数、压缩状态、来源版本、摘要和额外用量集中在「上下文路径」；对话详情的回答区不放统计框。点击圆形节点可查看其对应摘要，后来生成的摘要不会改变已有回答的上下文记录。

压缩仅改变发送给模型的上下文投影，原始消息、节点、工具记录与旧运行完整保留，JSON 导出包含原文和摘要。安全审批继续使用独立的原始用户请求、祖先证据和完整工具参数，摘要不会新增授权或抹去拒绝。分支仍共享当前磁盘文件，摘要中的文件与测试结果是历史记录，继续编码时仍需重新核对。

压缩失败、取消、超时或服务重启都会留下明确状态，不自动重放工具或重新发起付费调用。关闭自动压缩后，未显式选用摘要的请求继续使用原文；无法在模型预算内完成时会明确提示。

## 本地编码与审批

每个探索沿用创建时生成的固定空间 ID。未绑定本地项目时，工作目录默认为 `<PANEL_DATA_DIR>/workspaces/<空间 ID>/`（默认 `.panel/workspaces/<空间 ID>/`），在首次真实模型任务时创建。根节点详情显示可选中复制的空间 ID、当前目录完整路径及「临时目录」或「本地项目」标记。不同空间的默认目录相互独立，同一空间的所有分支共享目录。临时目录在服务重启后保留，不会自动清理；演示模型不创建临时目录，也不执行工具。

点击根节点卡片的「临时目录」（已连接时显示项目文件夹名）打开目录选择弹窗，也可在根节点详情浏览、填写并确认服务所在机器上的本地项目目录，或点击「使用临时目录」后确认恢复。两个入口共用草稿，关闭弹窗后仍可在详情中继续确认或取消修改。未保存的目录修改需要先确认或取消，才能从根节点发起任务。自选目录必须已存在且可访问，支持手动填写绝对路径和 `~/` 路径。有运行中或排队中的任务时，需要先结束或取消这些任务才能更换目录。切换目录只影响后续任务，不会迁移或删除原目录的文件；历史节点保留实际使用的目录快照。

选择真实模型后，无论使用临时目录还是本地项目，Panel 都直接复用 Pi harness 的四个原生工具：

| 工具    | 能力                                         |
| ------- | -------------------------------------------- |
| `read`  | 读取文件，可指定起始行和行数                 |
| `write` | 创建或覆盖文件，自动创建父目录               |
| `edit`  | 按原文精确替换一个或多个文本块               |
| `bash`  | 在工作目录执行命令，包括运行代码、测试和构建 |

工作台提供「请求批准」与「自动审批」切换按钮。默认使用**请求批准**：`read` 按只读策略执行，`write`、`edit`、`bash`、`web_search`、`web_fetch` 每次调用都展示参数，人工批准后才执行，也可以拒绝。

**自动审批由独立配置的安全模型审核，并非直接放行。** 在顶部主题区选择可用的真实安全模型，再开启自动审批；不会默认使用执行模型，也不能使用演示模型。此模式下每次本地或联网工具调用都把用户目标、当前分支背景、本轮已执行工具记录及完整调用参数交给安全模型。审核没有工具权限，只有返回明确的批准结论和理由后，原工具才会执行。安全审核会额外调用所选模型并产生相应用量。

安全模型拒绝、未配置、服务异常、60 秒超时、上下文超限或返回格式不明确时，操作转为人工审批，界面显示原因；可以人工批准这次操作或拒绝。审核期间可以停止节点；审核过程中切换模式或安全模型会使旧审核结果转为人工确认。已经签发但尚未派发执行的授权也会因设置变更而失效，此时工具返回失败，需要重新发起调用和审批。已经等待人工批准的操作不会因切换自动审批而被放行。

节点详情中的工具调用记录整块默认折叠，点击标题可展开查看参数、输出、错误及审批记录；折叠时仍显示操作数量和待批准、等待文件操作、进行中或失败提示。文件冲突只阻塞对应工具，等待原因显示在工具条目中，尚未执行时不会标为「执行中」。新记录不会自动展开，点击待审批入口会展开并定位对应操作。等待批准时可以切换节点，刷新页面后仍可继续审批；取消节点会结束待审批或文件等待操作，或中止正在运行的命令。服务重启后未完成任务及其工具记录会标明中断，不自动重放文件修改或命令。

每次批准都会产生有效期为 30 秒的单次执行授权，绑定探索、节点、工具调用 ID、工具名、完整参数、工作目录、审批模式和安全模型配置版本。最终工具执行入口重新匹配并原子消费授权；参数变化、重复消费、过期、设置变更、取消或保存失败均阻止执行。消费记录保存成功后才派发工具，派发前再次检查设置和取消状态。授权仅存于服务内存，磁盘上的授权 ID、动作 SHA-256、策略版本和签发、到期、消费/失效时间只用于审计，重启后不可恢复执行权限。摘要不包含脚本及外部文件的内容快照，不能防止其他进程在审核后替换文件。

等待文件锁期间不会消费授权。取得文件访问权限后、实际执行前重新检查 30 秒有效期、配置及取消状态；等待期间授权过期会明确拒绝执行，需要重新发起调用及审批，不会静默续签。

每个节点最多进行 40 次模型回复；达到上限时停止该轮并保留工具记录及已完成的文件修改。本地编码工具的界面输出最多保留末尾 20,000 个字符，联网工具记录保留插件返回的完整文本与来源；完整工具消息随成功节点保存并包含在 JSON 导出中。

`read`、`write`、`edit` 检查真实路径，只允许访问工作目录内的文件，拒绝通过 `../` 或符号链接访问目录外文件。`bash` 的默认超时为 120 秒，最多 600 秒；输出采用 Pi 的 2,000 行或 50 KB 限制，超出部分保存在临时日志中。**Shell 使用本机进程权限执行，并不是沙箱**；工作目录指定的是命令起始位置，命令仍可访问其他本机位置或网络。

Shell 不再自动继承服务端的完整环境变量，仅传递 PATH、HOME、用户名、语言、时区、临时目录及必要的 Windows 基础变量。模型 API 密钥、未知应用凭据、代理/SSH agent 配置，以及 BASH_ENV、ENV、NODE_OPTIONS、PYTHON\* 等启动配置不会自动传入。需要项目凭据的命令应在明确授权后单独配置。保留 HOME/PATH 意味着命令仍可主动读取本机配置或凭据文件，这项环境过滤不能替代文件和网络沙箱。

对话分支隔离的是消息上下文，**文件由所有分支共享当前磁盘状态**。回到历史节点、普通编辑重新生成或取消任务不会回滚已经写入的文件；失败卡片的「原地重试」会先恢复该轮有 Git 快照的文件。共享目录及父子目录内的节点可以并行，默认没有全局数量上限；等待审批不会占用文件锁或阻塞其他节点启动。

文件访问在工具执行阶段协调：多个 `read` 可以同时读取同一文件；`write`、`edit` 可同时修改不同文件，修改同一真实文件时依次执行，读取也会等待该文件的修改完成。符号链接按真实路径判定冲突；硬链接和所有 `bash` 均按未知影响范围处理，在实际文件操作和 Git 快照阶段与所有其他文件操作互斥，模型思考和联网查询仍可继续。批准前及等待文件时不会占住文件锁，取消等待不会阻塞其他分支。普通 `write`、`edit` 的 Git 快照只记录本次涉及的文件路径，避免把并行分支的修改混入当前记录；硬链接写入、编辑及所有 `bash` 按工作目录记录变化。

原地重试的文件恢复和空间删除仍使用目录维护互斥，同目录及父子目录存在活动任务时不能执行这些维护操作。节点排队时显示「等待目录维护完成」，工具冲突则显示具体文件等待原因。此协调仅覆盖当前 Panel 服务发起的操作，不提供分支文件隔离或外部程序的文件锁。

## 网页搜索与网页、PDF 读取

选择真实模型后即可使用联网工具，**不需要选择本地项目，也不需要搜索密钥**。Panel 通过适配层复用 [pi-web-access](https://github.com/nicobailon/pi-web-access) `0.29.0` 的 Exa 搜索和网页、PDF 文本提取，接入现有审批、取消和调用记录；本次只接入这些能力，未加载插件的其他工具或通用 Pi 扩展。

| 工具         | 能力                                                        | 配置                                   |
| ------------ | ----------------------------------------------------------- | -------------------------------------- |
| `web_fetch`  | 读取指定公开 HTTP(S) 网页、文本或 PDF，提取文本与来源网址   | 无需搜索密钥                           |
| `web_search` | 通过 Exa 搜索网页，返回结果与来源网址；支持结果数和时间范围 | 默认使用无密钥的 Exa MCP；可选 Exa API |

搜索默认使用 Exa MCP。如需使用 Exa API，可在项目 `.env` 中添加后重启服务：

```dotenv
EXA_API_KEY=你的_Exa_API_密钥
```

左下角「模型连接」可查看联网工具状态与当前 Exa MCP/API 模式。无密钥搜索仍需网络和远程服务可用；服务失败会明确报错，不生成虚构结果。搜索查询会发送给 Exa，网页读取会请求目标站点；请求批准模式下每次联网前由你确认，自动审批模式下由所选安全模型审核。工具活动显示实际查询或网址、结果和可点击的来源链接，便于核对。

读取支持公开 HTML、文本和 PDF，仅读取文本，不执行 JavaScript 或读取登录态。PDF 使用本地 `unpdf` 提取文字，不将原始 PDF 保存到工作目录；如需下载原文件，仍由批准后的 `bash` 保存到空间临时目录或已绑定的本地项目。扫描 PDF 的图片文字不在本次提取范围内。

每次调用在审批通过后启动独立进程，使用专用配置和临时目录；不加载用户的 Pi 配置或浏览器登录态，PDF 不上传远端解析。搜索与正文提取沿用所调用的 `pi-web-access` 引擎行为：Panel 不再对标题、摘要、网页或 PDF 文本追加字符截断，联网工具记录也保留返回全文和来源。插件自身的摘要策略及提取限制仍生效，PDF 当前默认最多 20 MB、100 页；这不表示取得原站全部内容，也不启用完整插件扩展的缓存分页工具。较长结果仍受所选模型上下文容量约束，按现有压缩与超限提示处理。

网络传输校验并固定公共 DNS 地址，逐跳检查重定向；响应最多 20 MB，超限明确报错。单次调用最多 60 秒，取消或正常服务关闭会终止进程并清理临时文件。

服务限制请求时长和响应大小，校验网址、DNS 地址与重定向，禁止本机、内网及其他非公开地址；不向目标网页传递浏览器登录态或服务端密钥。读取内容作为外部资料交给模型，不能据此改变审批规则。此限制适用于专用联网工具，Shell 的本机权限边界仍如上所述。

## MCP 扩展准备

项目已预装 [pi-mcp-adapter](https://github.com/nicobailon/pi-mcp-adapter) `2.34.0`，版本固定在 `package.json` 和锁文件中，随 `npm ci --ignore-scripts` 安装，用于后续接入更多 MCP 服务。

当前 Panel 直接创建 Pi Agent，尚未加载该适配器；添加 `.mcp.json` 或在 Pi CLI 中安装扩展不会自动为 Panel 启用 MCP 工具。后续接入需要配置服务、注册工具，并衔接现有审批、调用记录、取消与连接清理流程。macOS 打包目前也未包含该适配器，启用时需同步补充打包与验证。

## 文件更新快照

每次获准执行的普通写入、编辑按本次文件路径比较前后变化；硬链接写入、编辑及所有 Shell 操作按工作目录比较，有实际文件变化时保存真实 Git 快照。记录显示新增、修改、删除的文件、快照版本和关联节点；失败或取消前已产生的修改也会记录，只读操作和相同内容不会新增记录。

快照仓库位于 `<PANEL_DATA_DIR>/git-snapshots/`，按探索和目录隔离，不更改项目原有 Git 提交、暂存区或配置。需要本机已安装 Git；缺少 Git 或快照保存失败时显示独立错误，文件操作不会自动重试。记录在刷新及服务重启后保留；重新生成不清除历史，卡片删除后记录仍在，但不可再跳转。

快照遵循 `.gitignore`，排除 `.git`、`node_modules` 和 Panel 数据目录，符号链接只保存链接本身；不追踪 Shell 在工作目录外的修改，也不捕捉同一条命令中的每个中间写入。外部程序同时编辑时，只能确定变化发生在操作期间。此功能从启用后开始记录，不会补建历史文件版本；切换分支不会自动切换文件状态。

「原地重试」只回溯当前卡片当前运行版本涉及的文件，保留无关文件、旧运行和 Git 记录。快照缺失或后续文件变化冲突时会明确拒绝；纯文本失败和已确认无文件变化的操作可直接重试。恢复计划先持久化，服务重启可继续恢复文件，但不会自动重新调用模型；再次点击原地重试后才启动新运行。忽略文件、目录外修改和网络请求等命令副作用不在回溯范围内。

## 数据与运行

数据保存于 `.panel/state.json`，写入串行化并通过原子重命名落盘；流式过程每秒保存，节点创建/结束立即保存。浏览器关闭不终止运行。服务重启将未结束节点标为失败，不自动重复模型请求。

开发模式只对前端热更新。修改 `server/` 或服务端使用的共享代码后，需等待当前任务结束并重启服务。发送带卡片引用的任务前，前端会确认后端已加载引用功能；旧版本服务会明确提示重启，并保留草稿，不会仅发送引用标题而丢失正文。

可配置 `PORT`（默认 4317）、`PANEL_DATA_DIR`（默认 `.panel`）。服务只监听 `127.0.0.1`，设计用于本机单用户。不要对同一个数据目录同时启动多个服务实例。首版不提供账号或公开分享，工作目录、审批模式和工具记录随探索一起保存。

```bash
npm run check       # 前后端 TypeScript 检查
npm run test:setup  # 安装时的模型目录兼容与严格校验回归测试（无需联网）
npm run test:core   # 分支、审批、目录调度、本地与联网工具、取消、恢复、API 和 Pi 演示测试
npm run build      # 生成前端发布文件
npm start          # 本地生产模式，仍需要 node_modules 与 pi/ 源码
```
