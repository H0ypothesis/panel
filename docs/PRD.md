# Panel — 基于 Pi 的非线性 Agent 工作台

版本：v0.1（本地编码、联网、审批、上下文压缩、对话附件与卡片引用）· 2026-09-20 · 状态：当前开发与验收依据

## 1. 产品定义

Panel 是一个以对话图为主界面的 Agent 工作台。用户围绕一个问题展开多个方向，每一轮提问与回答组成一个节点，任意历史节点都可以成为下一轮探索的起点。画布保留探索的来龙去脉，右侧面板用于阅读、配置和继续对话。

首版基于当前目录中的 Pi 源码实现，使用 Pi Agent 运行时、多供应商模型接口、流式事件和原生编码工具。产品为本地运行、单用户、桌面优先的 Web 应用，界面默认中文。真实模型可搜索和读取公开网页，并在各空间默认的临时目录或自选本地项目目录执行文件操作、命令及联网工具；操作通过请求批准或安全模型自动审批执行。

**核心承诺：用户可以看见每次调用的上下文来源，可以保留分歧，可以并行探索，不必为了尝试一个新方向复制整段对话。**

## 2. 用户与核心场景

| 用户任务             | 操作                                            | 产品价值                     |
| -------------------- | ----------------------------------------------- | ---------------------------- |
| 研究一个复杂问题     | 从根问题分出市场、技术、用户等分支              | 多条思路同时可见             |
| 比较不同方案         | 从同一个节点创建多个子节点                      | 每个方案使用相同的前置上下文 |
| 比较模型或推理投入   | 从同一父节点使用不同模型、思考强度再次提问      | 比较时保留原始结果和配置     |
| 回到早期假设继续研究 | 选择历史节点，创建新分支                        | 后面的讨论不会污染新分支     |
| 整理研究结论         | 搜索节点、阅读路径、导出探索图                  | 能追溯结论如何产生           |
| 查找外部资料         | 让 Agent 搜索网页、读取网址并查看来源           | 查询与资料保留在分支上下文中 |
| 在本地项目编写代码   | 选择工作目录，让 Agent 读取、修改文件和执行测试 | 对话与实际项目工作连贯进行   |
| 控制工具执行权限     | 切换审批模式，逐项批准或拒绝待执行操作          | 执行前可查看路径、内容和命令 |

## 3. 信息架构与交互

桌面布局：左侧探索空间列表；中间无限画布；右侧节点详情与输入区。画布是主导航，对话面板随选中节点变化。

- 左侧：产品入口、新建探索、探索列表、当前探索的节点与分支统计、运行状态、连接设置；收起和展开使用平滑动画，隐藏后不可获得键盘焦点，窄屏使用抽屉；遵循减少动画的系统偏好。
- 每个探索空间右侧提供小 × 删除按钮，点击后打开二次确认面板，不切换当前空间。面板显示空间名称、节点数量和临时目录路径，默认保留临时文件；用户可勾选同时清理该空间的临时目录，自选本地项目目录始终保留。删除当前空间后切换到剩余空间，删除最后一个空间后显示新建入口。
- 品牌引导卡片不常驻侧栏；悬停或聚焦左上角 Panel 标识时在其下方浮出，支持进入卡片打开使用指南、按 Esc 关闭及触屏点击查看。
- 顶部：搜索、导出；探索标题、说明、运行数量及审批模式、安全模型选择位于可收起的主题区，统一收起和展开。
- 画布：根节点、轮次节点、有方向的连线；支持拖拽、缩放、平移、自动布局和适配画布。左上角默认展示全局缩略视图，显示全部节点、选中节点和当前视野，支持点击定位、拖动平移、滚轮缩放，并可通过画布工具栏隐藏或重新显示。节点颜色始终表示分支，不因运行状态改变；运行中卡片增加同色柔光高亮和动态虚线边框，完成后取消高亮和动态虚线、保持静态。底部提供状态图例，选中描边保持可见，减少动态效果模式保留静态虚线区分。
- 自动布局位于左下角画布工具栏；右上角 Git 记录默认折叠，用户可按需展开，按时间倒序显示文件更新、快照版本与关联问题。点击记录选中并定位对应卡片，同时收起记录面板。
- 轮次卡片：问题摘要、回答预览、模型、思考强度、状态、累计输入与输出 token 数字对、路径上下文圆环，以及“从这里分支”操作；非根节点增加编辑指令和删除入口。根节点卡片提供本地项目选择入口，点击后打开目录选择与确认弹窗。
- 分支入口位于卡片右侧连接点：悬停或键盘聚焦时显示圆形加号，点击后在画布打开临时草稿卡片，以虚线连接来源；连线中心保持原位。根节点及已完成、失败或已停止且上下文未过期、没有未完成文件回溯的节点可用；父链仍在收尾时不得提交。触屏上加号常显，右侧原有输入区仍保留。
- 右侧：选中节点的完整 Markdown 回答、该节点的执行参数、上下文路径、工具调用记录与审批操作、下一轮输入；对话输入框下方选择执行模型和思考强度，选中根节点时展示空间 ID、当前有效目录与目录类型，并提供本地项目选择和恢复临时目录操作。
- 对话详情中的工具调用记录整块默认折叠，用户点击标题后展开；折叠时显示调用数量及待批准、进行中或失败提示，新记录不会自动展开。点击待审批入口时展开并定位对应操作，切换节点或刷新后默认折叠。
- 分支输入区支持手动折叠；在阅读区向上滚动查看前文时自动收起为一行入口，点击入口或按 B 展开并聚焦输入。收起与展开采用 360ms 平滑过渡，高度、间距与透明度同步变化，并遵循系统减少动态效果设置。收起保留草稿与模型选择，隐藏控件不可获得焦点；节点切换、审批定位等程序滚动不触发自动收起。
- 点击节点只切换查看对象；发送时明确展示“从哪个节点继续”。新轮次完成前也可以切换到其他分支继续操作。
- 空探索展示可直接开始的引导；首次使用可打开清楚标注的示例探索。

视觉方向：浅暖灰背景、细线网点画布、白色节点卡片、深墨绿主色，以少量紫色、蓝色和橙色区分探索方向。布局重信息密度和长时间阅读。

主题支持浅色、深色和跟随系统三种模式，顶部提供始终可用的选择入口；默认跟随系统，系统外观变化时实时切换。手动选择保存在当前浏览器，刷新后恢复，首屏加载时应用主题以避免闪白。深色模式覆盖画布、节点、连线、小地图、详情、工具审批、表单和弹窗，并保持文字与状态可辨识。

## 4. 对话图与上下文规则（P0）

### 4.1 数据语义

视觉上是一张图，首版数据结构为**单根有向树**：除根以外，每个节点恰好有一个父节点。不支持多个父节点或随意连接节点，避免上下文来源不确定。

- 根节点：探索主题及背景信息，不消耗模型调用。
- 对话节点：一条用户问题及附件、显式选取的卡片引用快照 + 本轮完整 Agent 消息记录 + 回答文本 + 模型配置 + 工作目录与初始审批模式快照 + 工具调用记录 + 执行状态和统计；祖先重新生成后，后代以 `contextStale` 标记上下文已过期。
- 边：唯一表示上下文继承关系，不是普通装饰连线。
- 坐标属于展示信息，不会改变上下文顺序。

### 4.2 精确的上下文构造

例如：`根 → A → B`，同时存在 `A → C`。从 B 创建 D 时，D 的原始上下文为 `系统提示 + 根背景 + A 的完整轮次 + B 的完整轮次 + D 的问题及显式选择的引用卡片快照`；达到当前请求的压缩阈值或显式选用准备摘要时，可以将该父链的早期消息替换为可追溯摘要。C 默认不会进入 D 的上下文；若用户通过 `@` 选择 C，只加入 C 当时的问题和回答，不加入 C 的其他历史。

1. 服务端从父节点沿 parentId 回溯到根，校验无环、无断链，再反转为根到父节点顺序。
2. 从这条路径的完整 Pi 消息构造原始记录；保留供应商需要的消息字段，以支持跨模型续写。压缩仅生成每次模型请求的上下文投影，不改写节点原文或 Agent 的完整消息数组。
3. 每次运行保存实际祖先节点 ID 的快照、模型配置、自动压缩策略及实际使用的摘要记录；摘要绑定来源节点运行版本与内容 hash，不能通过客户端提交任意消息或另一条路径的摘要绕过路径规则。
4. 失败或已停止节点可“原地重试”：恢复本轮 Git 快照记录的文件后，以原问题和模型配置在同一卡片运行；“编辑指令”预填当前问题与模型配置，确认后在原节点重新生成，保留 ID 和位置。重跑使用根到父节点的有效路径、问题、附件和所选引用快照，旧的本轮消息、回答和工具结果不得混入新上下文；未修改引用时保留已保存的快照。
5. 根节点及已完成、失败或已停止且上下文有效、没有未完成文件回溯的节点可继续分支；父链中运行、排队、收尾或回溯未结束的节点不能作为新运行来源。失败或停止节点保留完整的已完成消息与工具结果，将不完整回答和缺失工具结果明确标为中断历史，不伪装为成功，也不自动重放工具。此投影不改写原始档案，来源计数与摘要校验以实际投影为准。上下文已过期的节点仍可查看，需沿父到子的顺序重新生成后才能继续分支。
6. 用户可打开上下文页，分别查看原始父链档案、本轮最近请求状态与摘要、以及手动为下一轮准备的摘要；不能将后来生成的摘要显示为已有回答使用过的上下文。当前上下文按最近一次调用的输入 tokens（含缓存）加该次生成 tokens 计算，生成期间更新估算，供应商返回后校准，明确标注来源；不能把多次调用的累计用量当作当前上下文。
7. 自动压缩默认开启，触发、结果、失败与额外用量可见；关闭自动压缩后，未显式选用准备摘要的请求使用原文，超过可用预算时明确失败。实际精确计数以供应商返回为准。
8. 消息上下文隔离不等于文件隔离。使用相同目录的分支共享当前磁盘文件，切换历史节点、普通编辑后重新生成、删除和取消均不回滚已完成的文件修改或命令效果；只有明确点击“原地重试”才按本轮 Git 快照恢复文件，界面须说明恢复范围。

每张卡片展示当前上下文圆环：使用本节点最近一次调用的 `lastRequestUsage.inputTokens + outputTokens`，输入含缓存读取、写入，输出仅取该次生成；此前各轮内容已计入最新输入，不能再次加上整段回答或累计 `usage.output`。生成期间更新本次输出估算并标记来源为估算，收到供应商完整计数后校准。该记录的时间必须不早于最近请求状态；新请求或压缩后尚无本次记录时使用 `contextState.inputTokens`，不沿用旧请求的输出；输出缺失或无效时暂不相加并标记估算。两者均缺失时才按可见原文字符数乘以 1.2 显示档案估算，并说明无法据此判断实际输入是否超限。容量优先使用运行保存的窗口，否则使用卡片执行模型的 `contextWindow`；尚未运行的根节点使用输入框当前所选模型。卡片去掉压缩状态文字和当前上下文/窗口分数，仅以 `49K / 1.8K` 这样的数字对展示该卡片任务累计输入与输出，不加「本轮」「输入」「输出」标签；悬停说明左侧为输入、右侧为输出，显示精确 token 计数，并说明统计为该任务内多次调用累计。圆环悬停说明输入与本次生成分项、计数来源、容量及独立保留的原文档案估算；鼠标使用普通箭头。低于 70% 为绿色，70% 至不足 90% 为琥珀色，达到 90% 为红色；容量未知显示 `—`，超过 100% 时圆环填满但数值不截断。上下文已过期的节点保留明确提示，不能把旧回答的计数当作可直接继续使用的有效上下文。

### 4.2.1 分支上下文压缩

- 原始对话树、各次运行的原始消息、工具记录及旧运行独立保存，摘要仅用于构建模型请求。JSON 导出保留原始记录和摘要，压缩不删除画布节点，不改写已完成回答，不改变文件状态。
- 自动压缩开关保存在探索上，默认开启，并在新运行创建时保存策略快照；修改开关只影响后续任务。每条路径、每次模型请求独立计算预算，A 分支发生压缩不使 B 分支自动改用摘要。B 尚未达到阈值且未显式选择摘要时，仍发送完整父链原文，即使共同祖先已有可复用摘要。
- 在首次模型请求以及工具结果追加后的下一次模型请求前检查容量；使用模型窗口、实际系统提示、工具定义及输出预留估算预算。基准保留近期约 20,000 tokens，预留约 16,384 tokens，并根据模型窗口与输出预算调整；单轮执行内也可以压缩已完成的早期工具组，不能只在节点提交前检查。
- 压缩后输入由原有系统提示、根背景、历史摘要、保留的近期原文和当前问题组成。摘要保存目标、用户约束、决策、进度、失败和拒绝、未完成事项及关键来源；文件内容与命令结果标明是历史状态，继续编码时仍需重新读取相关文件。
- 摘要 checkpoint 记录 ID、格式版本、覆盖消息数、来源节点 ID 与运行 revision、来源消息数、内容 hash、模型与思考强度、生成时间、前后估算 tokens 及额外模型用量。共同祖先摘要只有在覆盖前缀、运行版本与内容均匹配、且本次请求需要压缩或显式选用时才能复用；节点重新生成、删除或来源变更后不得误用旧摘要。生成过程中也须校验来源，迟到结果不能覆盖新版本。
- 切分保持完整消息与工具组边界，assistant 的一组工具调用及其全部结果不可被拆开；待审批或运行中的工具不进入可压缩前缀。保留当前问题和必要的近期消息，不能静默截断无法容纳的单条内容。
- 上下文页提供「压缩当前路径」，使用当前所选真实模型，明确说明产生额外用量；仅已完成、上下文有效的非根节点可用。同一节点不能重复并行生成准备摘要，生成时可以停止，也可切到其他分支继续工作。
- 手动压缩成功后自动在来源卡片之后显示圆形压缩节点，每份成功摘要都有独立圆点；多次压缩保留历史圆点，失败、取消不新增圆点。圆点「+」显式提交该 `contextCheckpointId`，原卡片「+」显式选择 `contextMode: raw`，不隐式借用该摘要；摘要路径和原文路径各自沿后代继承，原文超过可用预算时明确失败。普通未分流路径仍独立判断自动预算。摘要绑定草稿来源，切换查看其他节点不会改变已打开草稿的选择。压缩后第一张对话卡片的左侧入边以棕褐色加粗，后续卡片不重复标记；摘要失效后圆点仍可查看但不可继续。圆点为原始对话树的可视化投影，不插入伪造对话，不改变完整历史档案。
- 卡片底部只保留模型、思考强度、累计输入与输出数字对和上下文圆环，去掉未压缩/已压缩等提示与上下文/窗口数值；数字对不显示文字标签，悬停解释左右含义、精确计数及任务内多次调用累计的统计口径。圆环仍按最近调用的输入加输出占窗口比例计算。上下文页展示压缩状态、供应商实测或估算来源、输入与本次生成分项、压缩前后输入变化、来源版本、Markdown 摘要及额外用量；压缩前后比较只使用输入。对话详情回答区不放统计框。准备摘要不改变已有回答的实际上下文；原始父链档案始终完整保留。
- 压缩失败、取消、超时和服务重启须保存明确状态，不覆盖原始消息或可用摘要，不自动重复工具调用或恢复付费调用。只有仍满足预算时才可继续使用原始输入，否则明确停止并说明原因；原始错误不得被伪装成摘要成功。
- 安全审批继续使用独立的原始用户请求、祖先证据、工具记录与完整调用参数。工作模型生成的摘要不是新的用户授权，不能覆盖拒绝结果、恢复旧授权或放宽执行边界；审核证据不能因主对话压缩而丢失。

### 4.3 编辑指令与删除节点

- 仅非根节点提供编辑指令和删除按钮；点击按钮不触发卡片拖拽或创建分支。
- 编辑弹窗预填目标节点当前问题、执行模型和思考强度，用户可修改后确认重新生成。沿用原节点 ID、父节点和画布位置，从有效父路径构造新运行上下文，并使用当前审批设置审核新工具调用。
- 重新生成保留后代节点及其已有内容，将整棵后代子树标记为 `contextStale`。卡片和详情显示上下文已过期，禁止从过期节点继续分支；只有父路径有效时才可重跑该节点，按路径依次恢复，不能把旧后代回答静默当作新祖先上下文下的结果。
- 编辑或删除目标节点前，目标及其后代不得有运行中或排队任务；用户先停止相应任务，服务端仍须复核状态，防止界面打开后状态变化引发竞态。
- 删除确认弹窗显示目标问题、后代数量及删除范围。确认后删除目标与整棵后代子树，兄弟分支和根节点保持不变；删除后查看保留的父节点。
- 普通编辑重新生成和删除不回滚本机文件或已执行命令的副作用；新工具调用仍须经过当前审批流程。

### 4.3.1 失败卡片原地重试

- 失败及已停止的卡片和详情提供“原地重试”，使用原问题、执行模型和思考强度，保留节点 ID、父节点和画布位置，运行版本加一；旧运行与 Git 记录保留，后代按既有上下文过期规则处理。
- 先恢复当前节点当前运行版本涉及的文件：同文件多次修改以第一次修改前的状态为目标，恢复删除的文件、撤销新增的文件，并保留无关文件。使用该轮记录的真实执行目录，即使空间已切换项目也不改用新目录。
- 回溯前校验所有涉及文件的内容和权限，以及同文件各次快照的连续性；后续手动或其他分支修改发生冲突时明确拒绝，不覆盖后续文件，也不启动模型。缺失或失败的快照不能静默跳过；已确认无文件变化及纯文本失败可直接重试。
- 无文件变化的重试不等待其他分支。回溯按本轮涉及的全部文件原子加锁，同目录或父子目录存在其他运行、排队任务不构成拒绝理由；只等待冲突文件操作及其快照完成后核对内容，无关文件操作继续执行。恢复计划在文件变化前持久化，重复请求幂等；回溯中断后相关文件继续受保护，服务重启可继续文件恢复，但不自动启动模型或重放旧工具。
- 回溯仅覆盖 Git 快照中记录的工作目录内文件；忽略文件、工作目录外写入、网络请求及其他命令副作用不能通过此功能撤销。

### 4.3.2 失败或停止后在新节点继续

- 失败及已停止节点的右侧详情提供「在新节点继续」：使用右侧当前所选执行模型和思考强度，以默认续写提示直接创建子节点，请模型结合原问题、已有回答和工具结果完成余下工作。原节点及其错误、运行版本和画布位置保持不变。
- 用户也可在右侧输入自定义的后续要求，或通过来源卡片的 `+` 打开画布草稿并发送；三种入口均继承根到该失败或停止节点的有效路径，不跳回其父节点重新开始。
- 保留已有部分回答、已保存工具结果和当前磁盘文件，不恢复 Git 快照或重新执行历史工具。记录中未知或未完成的操作必须明确说明可能已有部分影响，后续模型应结合当前实际状态继续；新工具调用仍遵循当前审批、单次授权和文件访问规则。
- 来源及祖先上下文必须有效，且没有未完成文件回溯；服务端须拒绝仍在收尾的路径。不能通过新建子节点绕过待完成的原地重试回溯。创建请求使用现有幂等机制，重复提交不得创建重复子节点。
- 「原地重试」仍按第 4.3.1 节先恢复本轮文件后在同一卡片重新运行；在新节点继续保留当前进度，二者在界面中分别命名和说明。

### 4.4 画布草稿卡片

- 点击可用节点右侧加号，在画布打开临时草稿卡片，并以虚线标明来源。卡片包含问题输入、附件选择与拖放区、执行模型及其窗口容量、思考深度，以及取消和生成按钮；普通 Enter 换行，`⌘/Ctrl Enter` 提交。
- 新草稿继承来源节点模型配置；来源节点正被选中时，使用当前右侧输入区的配置。已有草稿恢复时保留用户已输入的文字、所选附件和配置，右侧原有输入区仍可独立使用。
- 每个探索同一时间展示一张草稿；切换来源节点或探索时，未取消的草稿保留在前端内存，刷新后不保留。取消只移除草稿，不创建正式节点，也不提交模型任务。
- 生成仍通过服务端创建正式节点；请求失败时保留草稿文字、附件与配置，使用同一请求 ID 重试，避免重复创建。正式节点坐标由服务端决定，不保证与临时草稿位置相同。
- 草稿记录来源路径及节点版本。来源或祖先上下文失效、节点版本变化时阻止提交，要求重新打开草稿确认当前路径后再生成，避免静默沿用变化前的上下文。

### 4.5 对话附件

- 右侧下一轮输入区和画布草稿卡片均支持选择或拖拽多个本地文件。发送前显示文件名、大小与类型，图片提供缩略预览，并可逐个移除；附件属于各自草稿，两个入口互不覆盖。文件读取期间禁止发送，失败显示原因并保留可用草稿。只有附件、没有文字时仍可发送，使用默认问题「请分析上传的附件。」。
- 每轮最多 5 个附件，单文件最大 10 MiB，合计最大 20 MiB，客户端及服务端均校验。支持 UTF-8 文本及代码文件（如 TXT、Markdown、CSV、JSON）、PDF 和 PNG/JPEG/WebP 图片。未知格式、无效编码、伪造格式、超限及解析失败明确报错，不创建半成品节点。
- 上传区提示大文件可改为在消息中发送本机文件的绝对路径，让模型按需选择读取方式；单文件或总大小超限的报错，以及已上传附件内容截断的提示，也提供这一替代方式。
- 文本和代码按文件名标注后进入本轮用户消息，每份最多发送前 100,000 个字符；PDF 在本机提取前 100 页且最多 100,000 个字符后进入消息，超出标记为部分内容，原件仍完整保存，不执行脚本、不上传至额外解析服务，不提供 OCR。图片使用 Pi 原生图像消息，要求所选真实模型支持图像输入；附件内容仍受模型上下文预算约束。演示模型可演练上传、查看和保存流程，但预设回答不表示真实理解附件。
- 附件与节点及运行版本关联，按真实父链进入上下文，兄弟分支互不污染；普通编辑重新生成和原地重试保留该节点附件，旧运行保留原件。上传不运行文件、不覆盖工作目录内同名文件，也不自动授予后续工具权限。
- 文件原件及提取内容随节点保存在本地数据目录，刷新和服务重启后可查看信息、下载原件；常规快照与 SSE 只发送附件元数据，不广播原件的 base64。尚未提交的附件仅存在浏览器草稿内，刷新后不保留。
- 删除节点及其子树或删除探索时，一并删除对应记录中的附件及旧运行副本。完整 JSON 导出携带附件原件并可重新导入；路径 Markdown 列出附件信息，不内嵌二进制文件。JSON 导入上限为 100 MiB，大量或多版本附件可能使导出超过导入容量，届时明确拒绝导入。

### 4.6 通过 @ 引用卡片

- 画布草稿卡片、右侧下一轮输入区和编辑指令弹窗均支持输入 `@` 打开候选框，继续输入可搜索当前探索中卡片的问题与回答。候选只包含已完成且上下文有效的非根卡片，已选卡片标记为已引用，重复选择不重复加入；不能跨探索选择，每轮最多引用 20 张。
- 支持鼠标选择，键盘 `↑` / `↓` 切换候选、`Enter` 确认、`Esc` 关闭；`⌘/Ctrl Enter` 保留发送行为，中文输入法组合输入期间不触发选择或发送。选中后在光标处插入卡片问题摘要，下方独立显示可移除的引用标签；取消候选不提交任务。引用与当前草稿一起保留，发送前可逐个移除，发送失败保留选择；实际引用以标签为准，未选取候选的普通 `@` 文本不会自动变成引用。
- 服务端在提交时校验来源并保存来源节点 ID、运行版本、问题和回答的快照。用户提交引用 ID，由服务端取得正文，不能通过创建或重新生成请求伪造来源内容。新增引用在提交前被删除、变为运行中或上下文失效时须明确报错。
- 引用只复制所选卡片本身的问题和回答，不复制祖先路径、工具调用、附件或该卡片引用的其他内容，也不递归展开。引用作为本轮用户消息中的资料参与模型调用和上下文预算，后续子节点沿正常父链继承；没有选择引用的其他分支仍按原父链隔离。
- 引用不会新增父节点或改变树连线、执行目录及文件状态。资料中的指令不构成新的用户目标或工具授权，仍使用原有审批流程。
- 已提交快照不随来源重新生成、上下文失效或删除而变化，旧运行也保留对应快照。原地重试和未修改引用的编辑重新生成沿用快照；节点详情及上下文页可查看来源版本、快照问题和回答，来源仍存在时可定位，已删除时显示快照仍保留。
- 「新分支重试」创建新节点，预填原问题及引用卡片选择，并在新节点提交时按来源当前版本重新保存快照。来源已删除、未完成或上下文失效时，需先移除不可用引用再提交；原节点及其已保存快照保留。
- JSON 导出、导入和本地持久化保留引用快照；导入重映射现存来源 ID，为已删除来源分配独立历史 ID，当前与旧运行的同一来源映射一致，不会误连其他卡片。缺少完整模型消息的历史导入仍用快照重建可读上下文。路径 Markdown 导出包含引用来源及快照正文。

## 5. 节点级模型配置（P0）

- 每次创建节点前，可在画布草稿或右侧对话输入框下方选择执行模型及思考强度；审批开关和安全模型选择保留在顶部可收起的主题区。收起主题区不影响输入区的模型选择，所选值保持不变。
- 支持 Anthropic、OpenAI、Google，以及无需凭证的 Pi 演示模型。
- 模型清单和思考等级从 Pi 模型目录读取，不在客户端猜测能力；无推理能力的模型仅显示“关闭”。
- 节点详情和模型选择器在模型名称旁以 K/M 格式显示上下文窗口容量；卡片容量放在圆环悬浮说明中，避免底部信息拥挤。容量不是本轮输出长度上限。
- 新节点优先继承选中节点配置，根节点使用当前默认配置。每次运行配置保存在对应节点，不受输入区后续选择影响；编辑指令时可显式修改该节点的下一次运行配置。
- 服务端校验模型存在、凭证可用、思考强度受支持。未配置的真实模型在选择器中标明不可用。
- API 凭证通过服务端环境变量配置；前端只接收配置状态和变量名，不读取或保存密钥。
- 演示模型必须持续显示“演示”，其回答和统计不得伪装成真实模型结果；即使绑定工作目录，也不授予演示模型本地或联网工具。

## 6. 本地工作目录与编码审批（P0）

### 6.1 工作目录

- 新建探索只填写主题和背景，沿用系统生成且不可修改的 UUID 作为空间 ID；现有探索也使用原有 ID。未绑定本地项目时，默认使用 `<PANEL_DATA_DIR>/workspaces/<空间 ID>/`（默认 `.panel/workspaces/<空间 ID>/`），在首次真实模型任务时创建。临时目录在重启后保留，不自动清理；演示模型不创建临时目录，也不注册本地或联网工具。
- 根节点详情展示可选中复制的空间 ID、当前有效目录的绝对路径，以及「临时目录」或「本地项目」标记；长路径在窄屏可换行。工作目录可从根节点卡片打开弹窗，或在根节点详情选择、确认、更换本地项目，亦可清除自选目录并确认恢复临时目录。两个入口共用目录草稿与保存逻辑，关闭弹窗后可在详情继续确认或取消修改。目录草稿未保存时禁止从根节点发送任务，支持取消修改恢复已保存值。
- 目录选择器浏览本机服务可访问的文件夹，也允许输入绝对路径或 `~/` 路径。服务端检查目录存在、可访问并保存解析符号链接后的真实路径。
- `workingDirectory` 仅保存用户选择的本地项目路径；服务端快照提供只读 `temporaryDirectory`，有效目录为前者或后者。每个真实模型节点提交时保存有效目录快照。切换目录只影响后续任务，不自动迁移或删除任何文件，历史节点目录快照保持不变。有运行或排队任务时禁止变更该探索的目录。
- 不同空间的默认目录独立，同一空间各分支共享文件。临时目录与自选目录使用相同的工具、审批、路径校验和调度规则；临时目录不构成系统沙箱。
- 启动编码任务前再次验证目录。目录已失效或实际路径发生变化时明确失败，不自动切换到其他位置。

### 6.2 编码工具与执行边界

- 真实模型在临时目录和自选目录均直接复用 `pi/packages/agent/src/harness/tools/` 中的 `read`、`write`、`edit`、`bash` 工厂和 `NodeExecutionEnv`，适配至现有 Pi Agent，不复制工具实现或修改 Pi 子模块。
- `read` 支持按行读取；`write` 创建或覆盖文件；`edit` 使用 `edits: [{ oldText, newText }]` 精确替换原文；`bash` 在所选目录运行代码、测试、构建等命令。
- 文件工具校验真实路径，拒绝 `../`、外部符号链接和悬空符号链接绕过工作目录边界；新文件路径也检查已存在的父目录。
- 命令默认超时 120 秒，上限 600 秒，支持独立取消及终止进程组。保留 Pi 的输出截断：最多最后 2,000 行或 50 KB，超出部分写入临时日志。
- 本地 Shell 使用服务进程的本机权限，**不提供操作系统沙箱**；工作目录只是命令起始位置，不限制命令访问其他目录或网络。根节点目录设置与工作台应明确显示此边界。
- Shell 以明确的基础环境变量白名单启动，强制关闭服务端环境继承；模型凭据、未知应用密钥、代理/SSH agent 和启动注入变量不自动传给子进程。此限制不阻止命令主动读取本机配置文件。
- 文件分支隔离、切换分支时自动回滚、独立 Git worktree 和容器均不属于本次实现；明确点击失败卡片“原地重试”时按本轮快照恢复文件。

### 6.3 审批模式与工具记录

- 默认模式为 `ask`（请求批准）：`read` 自动执行；`write`、`edit`、`bash`、`web_search`、`web_fetch` 每次执行前停下来等待批准，显示对应参数，并提供批准和拒绝操作。
- `auto`（自动审批）将每次本地和联网工具调用交给单独配置的安全模型。必须显式选择可用的真实模型，不能使用演示模型，也不默认复用执行模型。
- 安全审核是独立、无工具权限的单轮模型调用，输入包括用户目标、祖先问答、本轮之前的工具记录和本次完整参数。将这些内容视为待审数据，防止其中的指令覆盖审核规则；无法确认授权或风险时拒绝。严格要求结构化的批准/拒绝结论和理由，只有明确批准才执行。调用安全模型产生额外用量。
- 拒绝、配置缺失、不可用、60 秒超时、格式错误、上下文超限或网络错误均转为人工审批并展示原因，绝不默认放行。人工可以批准该次操作或拒绝；历史的直接自动放行记录必须明确标注旧版行为，不伪装成模型审核。
- 切换模式或安全模型不停止已派发执行的工具，已等待人工批准的调用保留原流程；审核进行中若设置发生变化，旧审核结果不得自动授权执行，转为人工确认。已经签发但尚未派发的授权失效，执行入口返回明确错误，需重新发起调用和审批。
- 服务端控制审批，不允许客户端仅改变显示状态就执行工具；一次批准只对应指定节点的指定工具调用，重复或过期审批返回明确错误。
- 批准后签发 30 秒有效、仅供单次执行的内存授权，绑定探索、节点、工具调用 ID、工具名、完整参数、工作目录、审批模式及安全模型配置版本。最终执行入口匹配并原子消费授权，消费记录保存后再次检查设置、有效期和取消状态再派发工具。变化、重放或保存失败均不执行。持久化授权摘要和策略版本用于审计，不得在重启后恢复执行权限；此机制不包含脚本/外部文件快照或操作系统隔离。
- 工具记录包括调用 ID、工具名、参数、状态、输出或错误、审批决定和时间，以及安全模型 ID、审核结论与理由。状态包括 `reviewing`、`awaiting_approval`、`running`、`completed`、`failed`、`denied`、`cancelled`，通过持久化和 SSE 同步；`running` 工具等待文件访问时附带 `waitingFor` 原因，界面显示「等待文件」或「等待文件操作」，不得误报为正在执行。取消和重启会中断审核，迟到的批准不得执行工具。
- 单个节点最多进行 40 次模型回复，达到上限明确停止并保留工具记录及已完成的文件修改，可按第 4.3.2 节在新节点继续。本地编码工具的界面输出保留末尾最多 20,000 个字符；`web_search`、`web_fetch` 的工具记录保留插件返回的完整文本与来源，不额外按字符截断。成功、失败和停止节点均保留已保存的原始 Pi 消息及工具记录用于后续上下文和 JSON 导出；中断记录不得被误报为成功结果。
- 拒绝操作不产生该工具的文件或命令效果，并向 Agent 返回拒绝结果；后续调用仍按当前模式审批。
- 取消节点时结束其待审批操作和运行中工具；刷新后仍能查看记录并处理有效审批。服务重启后待审批和运行中记录标记中断，不自动批准或重放。

### 6.4 网页搜索与网页、PDF 读取

- 通过 Panel 适配层复用 [pi-web-access](https://github.com/nicobailon/pi-web-access) `0.29.0` 的 Exa 搜索和网页、PDF 文本提取，保持 `web_search` 和 `web_fetch` 工具名，无需选择本地项目；演示模型不注册工具。本次不加载插件其他工具或提供通用 Pi 扩展加载能力。
- `web_search` 接受查询、结果数和时间范围，返回搜索结果和来源网址；默认使用无需密钥的 Exa MCP，服务端可选配置 `EXA_API_KEY` 使用 Exa API。设置页显示当前模式和可选密钥的配置说明，不暴露或编辑密钥。无密钥不代表离线可用，搜索服务失败时必须明确报错，不伪造结果。
- `web_fetch` 接受公开 HTTP(S) 网址，提取可阅读的 HTML、文本或 PDF 内容，无需搜索密钥。不执行网页 JavaScript，不读取登录态，不提供浏览器自动化。
- 搜索和网页/PDF 提取沿用所调用的插件引擎默认行为，移除 Panel 对标题、单条摘要、汇总摘要、正文和工具输出的固定字符裁剪。插件自身的摘要策略、提取大小及页数限制仍生效；不接入完整插件扩展的缓存/分页工具，不保证原站全部内容。返回内容完整进入 Pi 工具消息和联网工具记录；上下文容量不足时按现有压缩或明确超限流程处理，不静默截掉工具结果。
- PDF 使用本地 `unpdf` 提取文字，不对扫描图片进行 OCR，也不将原始 PDF 保存到工作目录；下载原文件仍需通过批准后的 `bash`，保存到当前空间临时目录或本地项目。
- 联网请求必须经过现有审批和单次执行授权；人工批准前或安全模型明确批准前不得请求搜索供应商或目标网页。审批界面说明查询会发送给搜索供应商、网页内容会交给对话模型。
- 服务限制请求时长、响应大小，校验网址、DNS 解析及每次重定向，禁止本机、内网和其他非公开地址；不使用浏览器 Cookie 或向目标网页传递服务端凭据。独立工具的网络约束不构成本机 Shell 沙箱。
- 将网页和搜索结果视为外部资料，不能覆盖工具权限与审批规则。工具记录保留查询、网址、结果与来源，界面只将有效 HTTP(S) 来源渲染为可点击链接；刷新和导出后可追溯。
- 未绑定本地项目的真实模型节点使用空间临时目录，保存有效目录、审批快照和工具记录，参与文件访问协调及目录维护互斥。

### 6.5 文件更新与 Git 快照

- 每次获准执行的普通 `write`、`edit` 按本次文件路径比较前后变化，硬链接写入、编辑及所有 `bash` 按有效工作目录比较；实际存在新增、修改或删除时保存一条独立 Git 快照并关联空间、节点 ID、节点运行版本、工具调用 ID、目录、时间及文件清单。只读命令、未改变内容的写入、未获批准的操作不生成更新记录；失败或取消前已经产生的文件变更仍保存快照。
- 快照保存在 `<PANEL_DATA_DIR>/git-snapshots/` 中，按空间和真实目录隔离，不修改项目原有 Git 历史、暂存区或配置，也不执行项目 Git hooks 或 clean filters。目录无需原先初始化 Git，但运行服务的机器需提供 Git。
- 按目录中的 `.gitignore` 规则记录可跟踪文件，排除 `.git`、`node_modules` 和嵌套的 Panel 数据目录；符号链接只记录链接本身，不跟随到目录外。工作目录外的 Shell 修改、忽略文件以及命令执行过程中已被再次覆盖的中间状态不在快照范围内。若外部程序同时修改文件，记录只表示该操作期间检测到的变化。
- 快照失败以单独错误记录显示，不将已执行的文件操作误报为未执行，也不自动重试工具。执行前持久化快照基线，服务中断后尝试补存实际变化并标记为恢复记录，绝不重放工具。扫描超时或容量超限明确报错。
- 记录独立于节点保存：重新生成保留各版本记录，删除卡片后保留快照且禁止跳转到不存在的节点。历史操作不能补建过去的文件版本；原地重试恢复当前轮次的已记录文件并标记相关记录已回溯，不修改用户原有 Git 提交、暂存区或配置。切换分支不自动切换文件版本。

## 7. 并行执行与恢复（P0）

每个执行节点创建独立 Pi Agent，拥有独立消息数组、取消信号和配置。同一空间可在 A 分支运行时提交并运行 B 分支；默认不限制全局运行节点数量，节点启动只需等待相冲突的目录维护操作，文件访问冲突在实际工具执行阶段协调。

- 状态机：`queued → running → completed | failed | cancelled`。
- 默认不设置全局节点并发数量上限；同一父节点可提交多个不同子节点，同一真实目录、符号链接对应的同一目录及父子目录内的节点均可并行。临时目录与本地项目遵守相同规则。
- 模型思考、联网查询、安全审核及等待人工批准不占用文件锁，也不阻塞其他节点启动。文件工具通过审批后才申请文件访问锁，锁仅覆盖实际执行及对应 Git 快照记录阶段。等待文件锁期间不消费授权；取得锁后、实际执行前重新检查 30 秒有效期、配置及取消状态，过期授权明确拒绝执行，需重新发起调用及审批，不得静默续签。
- `read` 对真实路径申请共享锁，同一文件可并发读取；`write`、`edit` 对真实路径申请排他锁，不同文件可并行，同一文件的修改以及与之冲突的读取依次执行。路径相同或互相包含时视为冲突，符号链接不能绕过锁。硬链接和所有 `bash` 均按未知影响范围处理，在文件操作及快照阶段保守使用全局文件互斥，其他节点的模型思考和联网查询仍可并行。
- 普通 `write`、`edit` 的 Git 快照限定到本次涉及的文件路径，不得混入并行分支对其他文件的修改；硬链接写入、编辑及所有 `bash` 在全局文件互斥下按工作目录记录变化。此协调只覆盖本服务内操作，不隔离分支文件版本，也不阻止外部程序修改文件。
- 原地重试按实际回溯文件协调，模型思考、联网查询和无关文件操作不阻塞重试；纯文本失败与已确认无文件变化的运行不获取文件锁。Shell、硬链接及涉及符号链接的恢复仍使用全局文件互斥。回溯准备及未完成回溯暂缓同目录新任务，删除空间仍要求同目录及父子目录活动任务结束。调度按提交顺序选取当前可运行的任务，等待目录维护的任务不阻塞其他可运行任务。节点排队显示「等待目录维护完成」；文件冲突保持节点运行状态，仅对应工具显示等待原因，已有回复时工具条目及折叠摘要仍须可见该等待状态。
- 每个节点独立流式更新，切换选中节点不应停止其他分支。
- 单节点取消只影响该节点；排队节点和等待文件的工具也可取消，取消后移除等待请求，文件操作结束后释放锁，不阻塞其他分支。取消不撤销已完成的文件修改或命令效果。
- 失败保留问题、配置、部分回答和可理解的错误；「在新节点继续」保留进度和文件创建子节点，“原地重试”先回溯本轮文件再以原配置运行，“编辑指令”可修改问题及配置后在原节点重新生成，后代按上下文过期规则处理。失败或停止状态不代表收尾已结束，后续运行须在收尾完成且路径有效、没有未完成回溯时启动。
- 浏览器刷新或断线后通过快照重新同步，后台任务继续运行。
- 服务重启时将未结束任务标记失败并说明“运行被服务重启中断”，不悄悄重复付费调用。
- 每次创建请求使用幂等请求 ID，网络重试不应导致重复运行。

## 8. 保存、检索与导出（P0）

- 多探索空间，本地服务端持久化；记录节点、消息、运行结果、上下文过期标记、拖拽坐标、工作目录、审批模式和工具记录。节点重新生成和子树删除通过快照与 SSE 同步。
- 删除探索空间前，服务端复核确认的节点范围，并拒绝仍有排队、运行或收尾操作的空间。清理临时目录只使用服务端按空间 ID 推导的路径，检查真实路径、符号链接及其他空间的目录占用；与自选项目目录重叠时拒绝清理。保存或清理失败必须明确报错并允许重试，服务重启不自动继续删除文件。
- 采用串行写入和原子替换，避免并行节点互相覆盖；保存失败必须可见。
- 搜索当前图的问题和回答，选择结果定位节点。
- JSON 导出保留整张图、运行配置、卡片引用快照与附件原件；Markdown 导出选中路径、引用来源与快照正文及附件清单，便于复用。
- 新建探索提供「创建空白」和「导入 JSON」。导入支持选择 Panel 导出的 JSON 文件，或填写服务所在机器上的绝对路径及 `~/` 路径，文件最大 100 MiB；选择文件时预览主题与节点数，导入成功后打开恢复的探索，可阅读其他人的分支及输出结果。
- 导入校验导出版本、字段及单根无环树，拒绝重复节点 ID、断链和无效格式；为探索与节点分配新 ID 并重映射父链，保留问答、布局、历史模型配置、用量、工具记录与附件原件，多次导入互不覆盖。无需原模型凭据即可查看；后续发起任务仍校验本机模型配置。
- 导入仅恢复对话资料，不恢复源工作目录、项目文件、Git 文件回溯、执行授权或压缩缓存，使用新空间临时目录并重置为请求批准。未完成节点、待审与执行中工具标记中断，不触发模型调用或重放；保存成功后才发布新探索，失败可重试。
- 视口偏好保存在本地浏览器；后端数据目录不纳入版本控制。

API 概览：

JSON 导入接口：`POST /api/workspaces/import` 接收 `{ data }` 导出内容或 `{ path }` 本机 JSON 文件路径，校验并创建独立探索，返回 `workspaceId` 和最新快照。

| 接口                                                              | 职责                                                                                                                                                  |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/state`、`GET /api/events`                               | 获取快照与 SSE 更新，含工具和审批状态                                                                                                                 |
| `GET /api/models`                                                 | 模型目录与连接状态                                                                                                                                    |
| `GET /api/capabilities`                                           | 网页/PDF 读取能力、Exa MCP/API 模式、可选密钥变量名及插件版本；不返回密钥值                                                                           |
| `GET /api/directories?path=...`                                   | 返回已验证目录、父目录和可浏览子目录                                                                                                                  |
| `POST /api/workspaces`                                            | 创建探索，接受 `workingDirectory`、`approvalMode` 和 `safetyModel`；自动审批必须选择安全模型                                                          |
| `PATCH /api/workspaces/:id`                                       | 更新目录、审批模式、安全模型或 `autoCompact`；压缩设置对后续任务生效；`safetyModel` 可设为 `null` 清除，自动审批模式下必须有效                        |
| `DELETE /api/workspaces/:id`                                      | 接收 `expectedNodeIds` 和 `deleteTemporaryDirectory`，删除确认的探索空间，可选清理其临时目录；返回最新快照                                            |

| `POST /api/workspaces/:id/nodes/:nodeId/compact`                  | 接收 `config`、`expectedRevision`、`requestId`，为有效已完成节点生成下一轮摘要；返回 `checkpointId`（如有）和最新 `state`，不更改已有回答的实际上下文 |
| `POST /api/workspaces/:id/nodes/:nodeId/regenerate`               | 接收新指令、模型配置、请求 ID 和预期 revision，可提交 `referenceNodeIds` 更新引用，省略时沿用快照；在原节点重新生成，后代标记为上下文失效             |
| `POST /api/workspaces/:id/nodes/:nodeId/retry`                    | 接收请求 ID 与预期 revision，先恢复失败/取消节点本轮文件，再以原配置原地重试                                                                          |
| `DELETE /api/workspaces/:id/nodes/:nodeId`                        | 核对预期 revision 与确认的节点 ID 集合，删除节点及其子树                                                                                              |
| `PATCH /api/workspaces/:id/nodes/:nodeId`                         | 仅修改节点坐标                                                                                                                                        |
| `POST /api/workspaces/:id/nodes/:nodeId/approvals/:toolId`        | 提交 `{ decision: "approve" \| "deny", expectedRevision }`，仅处理对应节点版本的一次有效审批                                                          |
| `POST /api/workspaces/:id/nodes/:nodeId/cancel`                   | 取消节点及待审批或执行中的工具；已完成节点正在准备摘要时仅停止摘要生成，保留已完成状态                                                                |
| `GET /api/workspaces/:id/nodes/:nodeId/attachments/:attachmentId` | 下载该节点附件原件                                                                                                                                    |
| `GET /api/workspaces/:id/export`                                  | 导出完整探索或选中路径                                                                                                                                |

服务默认绑定 loopback，仅用于本机；变更请求校验 Origin 和 JSON Content-Type，不开放跨域。API 不返回任何密钥。

## 11. 验收标准

1. 从示例或新建探索进入画布，节点与连线正确显示，拖拽位置刷新后仍在。
2. 从根节点及上下文有效、没有未完成文件回溯的已完成、失败或已停止祖先节点新建分支，原分支保留；服务端测试证明未显式引用的兄弟与后代内容不进入上下文，引用只加入所选有效已完成卡片的问题和回答。
3. 在同一空间同时发起至少四个真实模型运行，各节点均实时更新，验证默认没有全局 3 个节点上限；模型思考、联网查询和审批不会因共享目录而整轮串行。取消其中一个，其他节点正常完成；跨空间运行同样不设默认数量上限。
4. 每个新节点可以单独设置模型/思考强度，详情显示该次运行的真实配置。
5. 真实模型未配置时给出明确配置指引，不伪造成功；演示模式可完整演练上述流程。
6. 上下文页展示实际父链；失败卡片“原地重试”恢复本轮文件后使用原配置重新运行，“编辑指令”在原节点重新生成且保留 ID、父节点及画布位置，旧本轮消息不进入新运行上下文。
7. 重复提交相同请求 ID 只创建一个节点；队列、错误、取消和服务重启均可恢复为明确状态。
8. 多个探索的内容相互隔离，搜索可定位节点，JSON 和 Markdown 可导出。新建探索可通过文件选择或 JSON 路径导入导出结果，问答、分支和布局正确，刷新及重启后保留；重复导入不覆盖原空间，错误文件不创建探索，不恢复源目录或自动执行任何历史任务和审批。
9. TypeScript 检查及核心行为测试通过；在浏览器验证主流程和至少一种较窄窗口。
10. 新建与现有探索均可通过根节点卡片或详情选择有效目录，或清除自选目录并恢复临时目录，两处状态同步且刷新后保留；根详情显示空间 ID、有效目录和目录类型，窄屏长路径可读；无效目录明确报错，有活动任务时禁止更换目录。
11. 使用临时目录验证实际读取、写入、精确编辑、运行代码、命令失败、超时、取消和输出截断；目录外路径和符号链接不能绕过文件工具边界。
12. 请求批准模式下，读操作直接执行，写入、编辑和命令在批准前不产生效果；批准、拒绝、取消、刷新和重启均留下明确状态。
13. 自动审批必须调用所配置的安全模型，批准前无文件或命令效果；拒绝、审核异常、无配置均转人工。切换模式不放行已等待批准的调用；审核中取消、重启或更换设置后，旧结果不得自动执行。
14. 同目录及父子目录内不同文件的写入、编辑可并行，同一文件修改互斥，同一文件可并发读取但不能与修改重叠；符号链接不能绕过冲突保护。硬链接和 `bash` 文件操作及快照阶段使用全局文件互斥，模型思考和联网查询继续推进。等待原因在画布状态和工具条目中明确显示，取消等待后其他分支正常推进；并行文件工具的 Git 记录不得包含其他分支的修改。恢复按涉及文件互斥，删除保持目录维护互斥。
15. 界面明确说明本机 Shell 非沙箱、分支共享文件、取消不回滚；演示模型即使绑定目录也不执行工具。自动化测试与浏览器验收不能替代真实供应商端到端验证，未经实际调用不得宣称已经验证远程模型。
16. 浅色、深色和跟随系统均可切换；默认及跟随系统模式响应系统外观变化，手动模式不受系统变化影响，刷新后保留选择。画布、小地图、详情和弹窗主题一致，窄屏与收起主题区后仍能操作主题选择。
17. 未绑定本地项目的真实模型可使用网页/PDF 读取及默认无需密钥的 Exa MCP 搜索，并可通过批准后的 `bash` 将文件下载到空间临时目录；可选密钥启用 Exa API，设置页显示当前模式。联网操作在批准前不发送请求，拒绝或取消后不执行；来源链接随记录保存。PDF 提取不将原文件写入工作目录。
18. 联网工具拒绝非 HTTP(S)、本机与内网地址，并验证 DNS、重定向、超时、响应大小和取消；不能通过返回内容改变审批规则。未实际调用搜索供应商时不得宣称已验证真实搜索服务。
19. 非根节点编辑弹窗预填问题与模型配置；重跑后保留后代并标记上下文过期。过期节点不可分支，须从有效父路径逐个重跑；刷新后标记保留，兄弟分支不受影响。
20. 删除确认展示目标与后代数量，实际删除范围与提示一致，根节点不可删除。目标或后代有运行、排队任务时禁止编辑和删除；操作不回滚文件或命令效果。
21. 新旧空间未绑定本地项目时，首次真实模型任务创建以固定空间 ID 命名的临时目录，四项本地工具与审批正常生效；同空间节点可并行，文件冲突按工具粒度等待，不同临时目录遵守相同规则。目录刷新及重启后保持一致，文件不自动清理；切换本地项目再恢复临时目录不迁移或删除文件，历史任务保留执行目录快照。演示模型不创建临时目录。

22. 左下角可执行自动布局；右上角 Git 记录可收起、滚动查看并定位对应卡片。实际写入、编辑及 Shell 增删改生成真实 Git 快照，重复内容/只读/拒绝不记；失败或取消后的部分修改可追溯。刷新、重新生成、删除节点及服务重启后记录保持正确，项目原有 HEAD 与暂存区不变。

23. 失败和已停止的卡片均可原地重试；验证本轮文件增删改回溯、后续冲突不覆盖、原执行目录保持、无变更与纯文本失败、幂等及中断恢复。其他任务或无关文件操作运行期间可以重试，无文件变化时即使存在 Shell 操作也不等待；冲突文件操作完成后必须重新检查内容，回溯中断后现有任务不得覆盖待恢复文件。回溯失败不得启动模型，重复点击不创建新卡片，不重放旧工具，原 Git HEAD 与暂存区不变。

24. 探索空间的小 × 打开二次确认，取消不删除；默认保留临时文件，勾选后只清理该空间临时目录，本地项目文件不受影响。活动任务、确认范围变化、路径越界及保存/清理失败均明确拦截或报错。删除当前空间、非当前空间及最后一个空间后界面和刷新状态正确，窄屏下确认面板可操作。

25. 构造共享祖先的两条路径：A 到达自动压缩阈值后只改变 A 的请求投影；B 未达阈值、未显式选择摘要时仍使用完整原文。手动压缩在画布产生圆点，从圆点创建的任务及后代使用对应摘要，从原卡片创建的原文任务及后代保留原文，互不影响；只有圆点后的第一张卡片有棕褐色左边框。多次手动压缩保留历史圆点与分支来源；来源版本/hash失效拒绝复用。

26. 首次请求和单节点多轮工具执行期间均能触发压缩，原始消息、父链、工具记录及完整 JSON 导出不减少；工具调用与结果成组保留，当前问题不能丢失。祖先重新生成、删除或生成途中版本变化时拒绝旧摘要；摘要不能绕过原有安全审核与一次性授权。

27. 自动设置刷新后保留且仅影响后续运行；界面区分本轮摘要与下一轮准备摘要，展示状态、前后估算、来源、正文和额外用量。验证压缩失败、取消、超时、重启、重复请求及其他分支并行场景，不自动重放工具或付费调用；浅色、深色、窄屏和主题区收起时均可查看和操作。

28. 右侧输入区与画布草稿均可选择、拖拽、预览和移除多个附件，纯附件可发送；超限、无效格式和解析失败有明确提示，失败保留草稿。文本/PDF 提取文字及图片原生输入进入正确父链，兄弟分支隔离；刷新、服务重启、重新生成及原地重试保留附件，JSON 导出导入和原件下载可用，Markdown 列出信息，删除节点或探索后记录内附件一并清理。

29. 画布草稿、右侧输入区和编辑弹窗输入 `@` 可搜索并选择同探索有效已完成卡片，鼠标和键盘均可操作、移除引用；空结果和 20 张上限有明确提示。提交后模型上下文仅增加选中卡片问答快照，来源版本可查看，父链不变，未选分支及引用来源的祖先、工具、附件和递归引用不会混入。来源更新或删除、刷新、服务重启、原地重试、未修改引用的编辑重新生成、JSON 导出导入和 Markdown 导出均保留已提交快照；新分支重试预填引用选择，并在新节点提交时重新校验与保存来源当前内容。新增无效引用明确拒绝，重复请求不创建重复节点。

30. 失败和已停止节点可通过右侧「在新节点继续」、自定义后续输入及画布 `+` 创建子节点；快捷继续使用当前所选模型、思考强度和默认续写提示。覆盖已完成工具后失败、部分回答后失败、审批时停止、达到执行上限和服务重启中断，确认原卡片、已保存结果及当前文件保留，新上下文包含实际父链和明确中断状态，不自动重放工具，新调用正常审批。收尾、运行、排队、过期路径及未完成文件回溯均拒绝继续；重复请求只创建一个子节点。验证中断投影的来源校验与自动压缩、继续后的再次分支，以及原地重试仍回溯本轮文件并使已有后代过期。此规则不扩大 `@` 候选范围，失败和已停止节点仍不能作为新引用选择。

## 13. 需求清单与状态

更新日期：2026-09-20。多子 Agent 与合并对话为后续需求，未纳入当前版本验收；文件上传已实现并纳入 v0.1，详细规则见第 4.5 节。

- [ ] **支持多子 Agent**：主 Agent 可以派发多个子任务，子 Agent 独立执行并返回结果，由主 Agent 汇总。
- [ ] **支持合并对话**：用户可以选择多条对话或分支，将内容汇总为新的对话起点并继续提问。
- [x] **支持文件上传**：用户可以把本地文件作为对话附件提交，供 Agent 读取和分析。
- [x] **支持 @ 引用卡片**：输入 `@` 搜索并选择同探索卡片，将其问题与回答作为快照加入本轮上下文；规则与验收见第 4.6 节和第 11 节第 29 项。

### 13.1 多子 Agent

- 功能目标：在一个任务中拆分工作并支持多个子 Agent 并行协作；界面可查看主从关系、子任务目标、运行状态、输出和用量。这项能力包含任务委派与结果汇总，现有多个对话节点并行仍作为独立能力保留。
- 初步约束：子 Agent 的上下文来源、模型配置及工具记录可追溯，沿用现有审批与文件访问协调规则；子任务失败、取消及服务重启有明确状态，不自动重放工具或恢复付费调用。
- 待明确：由用户还是主 Agent 发起拆分、子 Agent 模型选择、是否允许递归委派、并发与用量限制，以及取消主任务时对子任务的处理方式。
- 验收方向：同一主任务派发至少两个子任务并汇总结果；可独立查看和取消子任务，其他子任务按约定继续运行，工具审批和文件冲突处理有效。

### 13.2 合并对话

- 功能目标：选择多条对话或分支，预览合并范围，生成新的合并节点并从该节点继续对话；保留原始节点、分支及来源引用。
- 初步约束：明确展示实际使用的来源节点、运行版本及内容，合并只影响新对话的上下文，不合并文件版本。现有单父链规则继续适用于当前版本；后续需明确合并节点的数据结构、上下文构造、压缩及导入导出规则，不能仅通过画布连线隐式合并。
- 待明确：首期是否仅支持同一探索内合并、采用原文组合还是总结节点、共同祖先去重方式、冲突观点如何呈现，以及来源重新生成或删除后的失效策略。
- 验收方向：合并两条分支后可继续提问，来源可追溯且原分支保留；未选择的分支不会混入，超出上下文预算或来源过期时给出明确处理结果。

### 13.3 文件上传（已实现）

右侧输入区和画布草稿卡片均支持附件选择与拖放，覆盖 UTF-8 文本/代码、PDF 文本提取和 PNG/JPEG/WebP 图片。支持草稿预览移除、父链上下文继承、原件保存下载、重跑保留、JSON 导出导入和记录删除时清理；限制及验收见第 4.5 节和第 11 节第 28 项。OCR、Office 文档解析和任意二进制格式不在本次范围内。

技术依据：本地 `pi/packages/agent/README.md`、`pi/packages/ai/README.md` 与对应源码；[Pi 官方网站](https://pi.dev/)。
