# Panel — 基于 Pi 的非线性 Agent 工作台

版本：v0.1（本地编码、联网与审批扩展）· 2026-09-18 · 状态：当前开发与验收依据

## 1. 产品定义

Panel 是一个以对话图为主界面的 Agent 工作台。用户围绕一个问题展开多个方向，每一轮提问与回答组成一个节点，任意历史节点都可以成为下一轮探索的起点。画布保留探索的来龙去脉，右侧面板用于阅读、配置和继续对话。

首版基于当前目录中的 Pi 源码实现，使用 Pi Agent 运行时、多供应商模型接口、流式事件和原生编码工具。产品为本地运行、单用户、桌面优先的 Web 应用，界面默认中文。真实模型可搜索和读取公开网页，并在各空间默认的临时目录或自选本地项目目录执行文件操作、命令及联网工具；操作通过请求批准或安全模型自动审批执行。

**核心承诺：用户可以看见每次调用的上下文来源，可以保留分歧，可以并行探索，不必为了尝试一个新方向复制整段对话。**

## 2. 用户与核心场景

| 用户任务             | 操作                                            | 产品价值                     |
| -------------------- | ----------------------------------------------- | ---------------------------- |
| 研究一个复杂问题     | 从根问题分出市场、技术、用户等分支              | 多条思路同时可见             |
| 比较不同方案         | 从同一个节点创建多个子节点                      | 每个方案使用相同的前置上下文 |
| 比较模型或推理投入   | 从同一父节点使用不同模型、思考强度再次提问      | 比较时保留原始结果和配置     |
| 回到早期假设继续研究 | 选择历史节点，创建新分支                        | 后面的讨论不会污染新分支     |
| 整理研究结论         | 搜索节点、阅读路径、导出探索图                  | 能追溯结论如何产生           |
| 查找外部资料         | 让 Agent 搜索网页、读取网址并查看来源           | 查询与资料保留在分支上下文中 |
| 在本地项目编写代码   | 选择工作目录，让 Agent 读取、修改文件和执行测试 | 对话与实际项目工作连贯进行   |
| 控制工具执行权限     | 切换审批模式，逐项批准或拒绝待执行操作          | 执行前可查看路径、内容和命令 |

## 3. 信息架构与交互

桌面布局：左侧探索空间列表；中间无限画布；右侧节点详情与输入区。画布是主导航，对话面板随选中节点变化。

- 左侧：产品入口、新建探索、探索列表、当前探索的节点与分支统计、运行状态、连接设置；收起和展开使用平滑动画，隐藏后不可获得键盘焦点，窄屏使用抽屉；遵循减少动画的系统偏好。
- 品牌引导卡片不常驻侧栏；悬停或聚焦左上角 Panel 标识时在其下方浮出，支持进入卡片打开使用指南、按 Esc 关闭及触屏点击查看。
- 顶部：搜索、导出；探索标题、说明、运行数量及审批模式、安全模型选择位于可收起的主题区，统一收起和展开。
- 画布：根节点、轮次节点、有方向的连线；支持拖拽、缩放、平移、自动布局和适配画布。左上角默认展示全局缩略视图，显示全部节点、选中节点和当前视野，支持点击定位、拖动平移、滚轮缩放，并可通过画布工具栏隐藏或重新显示。
- 自动布局位于左下角画布工具栏；右上角展示可折叠的 Git 记录，按时间倒序显示文件更新、快照版本与关联问题。点击记录选中并定位对应卡片，同时收起记录面板。
- 轮次卡片：问题摘要、回答预览、模型、思考强度、状态、路径上下文圆环，以及“从这里分支”操作；非根节点增加编辑指令和删除入口。根节点卡片提供本地项目选择入口，点击后打开目录选择与确认弹窗。
- 分支入口位于卡片右侧连接点：悬停或键盘聚焦时显示圆形加号，点击后在画布打开临时草稿卡片，以虚线连接来源；连线中心保持原位。仅根节点及已完成且上下文未过期的节点可用，触屏上加号常显；右侧原有输入区仍保留。
- 右侧：选中节点的完整 Markdown 回答、该节点的执行参数、上下文路径、工具调用记录与审批操作、下一轮输入；对话输入框下方选择执行模型和思考强度，选中根节点时展示空间 ID、当前有效目录与目录类型，并提供本地项目选择和恢复临时目录操作。
- 点击节点只切换查看对象；发送时明确展示“从哪个节点继续”。新轮次完成前也可以切换到其他分支继续操作。
- 空探索展示可直接开始的引导；首次使用可打开清楚标注的示例探索。

视觉方向：浅暖灰背景、细线网点画布、白色节点卡片、深墨绿主色，以少量紫色、蓝色和橙色区分探索方向。布局重信息密度和长时间阅读。

主题支持浅色、深色和跟随系统三种模式，顶部提供始终可用的选择入口；默认跟随系统，系统外观变化时实时切换。手动选择保存在当前浏览器，刷新后恢复，首屏加载时应用主题以避免闪白。深色模式覆盖画布、节点、连线、小地图、详情、工具审批、表单和弹窗，并保持文字与状态可辨识。

## 4. 对话图与上下文规则（P0）

### 4.1 数据语义

视觉上是一张图，首版数据结构为**单根有向树**：除根以外，每个节点恰好有一个父节点。不支持多个父节点或随意连接节点，避免上下文来源不确定。

- 根节点：探索主题及背景信息，不消耗模型调用。
- 对话节点：一条用户问题 + 本轮完整 Agent 消息记录 + 回答文本 + 模型配置 + 工作目录与初始审批模式快照 + 工具调用记录 + 执行状态和统计；祖先重新生成后，后代以 `contextStale` 标记上下文已过期。
- 边：唯一表示上下文继承关系，不是普通装饰连线。
- 坐标属于展示信息，不会改变上下文顺序。

### 4.2 精确的上下文构造

例如：`根 → A → B`，同时存在 `A → C`。从 B 创建 D 时，D 使用 `系统提示 + 根背景 + A 的完整轮次 + B 的完整轮次 + D 的问题`；C 不会进入 D 的上下文。

1. 服务端从父节点沿 parentId 回溯到根，校验无环、无断链，再反转为根到父节点顺序。
2. 只加入这条路径的完整 Pi 消息；保留供应商需要的消息字段，以支持跨模型续写。
3. 每次运行保存实际祖先节点 ID 的快照和模型配置，不能通过客户端提交任意消息绕过路径规则。
4. “新分支重试”创建兄弟节点并保留原结果；“编辑指令”预填当前问题与模型配置，确认后在原节点重新生成，保留 ID 和位置。重跑只使用根到父节点的有效路径及修改后的问题，旧的本轮消息、回答和工具结果不得混入新上下文。
5. 已成功且上下文未过期的节点可继续分支。运行、失败、取消和上下文已过期的节点均可查看；失败或取消可重跑，过期节点需沿父到子的顺序重新生成，恢复有效上下文后才能继续分支。
6. 用户可打开上下文页，查看根背景与实际继承的每轮问答；上下文的 token 数为估算，明确标注。
7. 首版不静默压缩历史；保守估算超过模型上下文预算时拒绝启动并给出说明。实际精确计数以供应商返回为准。
8. 消息上下文隔离不等于文件隔离。使用相同目录的分支共享当前磁盘文件，历史节点、重试、编辑后重新生成、删除和取消均不回滚已完成的文件修改或命令效果；界面必须说明这一点。

每张卡片展示路径上下文圆环：按根到该卡片的可见问题、回答和工具参数、输出字符数乘以 1.2 估算 token 数，以该卡片执行模型的 `contextWindow` 为参考容量；尚未运行的根节点使用输入框当前所选模型。悬停说明估算值、容量及局限，不使用累计调用用量 `usage` 代替上下文占用，也不将估算称为精确剩余容量。低于 70% 为绿色，70% 至不足 90% 为琥珀色，达到 90% 为红色；容量未知显示 `—`，超过 100% 时圆环填满但数值不截断。上下文已过期的节点保留明确提示，不能把旧回答的估算当作可直接继续使用的有效上下文。

### 4.3 编辑指令与删除节点

- 仅非根节点提供编辑指令和删除按钮；点击按钮不触发卡片拖拽或创建分支。
- 编辑弹窗预填目标节点当前问题、执行模型和思考强度，用户可修改后确认重新生成。沿用原节点 ID、父节点和画布位置，从有效父路径构造新运行上下文，并使用当前审批设置审核新工具调用。
- 重新生成保留后代节点及其已有内容，将整棵后代子树标记为 `contextStale`。卡片和详情显示上下文已过期，禁止从过期节点继续分支；只有父路径有效时才可重跑该节点，按路径依次恢复，不能把旧后代回答静默当作新祖先上下文下的结果。
- 编辑或删除目标节点前，目标及其后代不得有运行中或排队任务；用户先停止相应任务，服务端仍须复核状态，防止界面打开后状态变化引发竞态。
- 删除确认弹窗显示目标问题、后代数量及删除范围。确认后删除目标与整棵后代子树，兄弟分支和根节点保持不变；删除后查看保留的父节点。
- 编辑、重新生成和删除均不回滚本机文件或已执行命令的副作用；重新生成中的新工具调用仍须经过当前审批流程。

### 4.4 画布草稿卡片

- 点击可用节点右侧加号，在画布打开临时草稿卡片，并以虚线标明来源。卡片包含问题输入、执行模型及其窗口容量、思考深度，以及取消和生成按钮；普通 Enter 换行，`⌘/Ctrl Enter` 提交。
- 新草稿继承来源节点模型配置；来源节点正被选中时，使用当前右侧输入区的配置。已有草稿恢复时保留用户已输入的文字和所选配置，右侧原有输入区仍可独立使用。
- 每个探索同一时间展示一张草稿；切换来源节点或探索时，未取消的草稿保留在前端内存，刷新后不保留。取消只移除草稿，不创建正式节点，也不提交模型任务。
- 生成仍通过服务端创建正式节点；请求失败时保留草稿文字与配置，使用同一请求 ID 重试，避免重复创建。正式节点坐标由服务端决定，不保证与临时草稿位置相同。
- 草稿记录来源路径及节点版本。来源或祖先上下文失效、节点版本变化时阻止提交，要求重新打开草稿确认当前路径后再生成，避免静默沿用变化前的上下文。

## 5. 节点级模型配置（P0）

- 每次创建节点前，可在画布草稿或右侧对话输入框下方选择执行模型及思考强度；审批开关和安全模型选择保留在顶部可收起的主题区。收起主题区不影响输入区的模型选择，所选值保持不变。
- 支持 Anthropic、OpenAI、Google，以及无需凭证的 Pi 演示模型。
- 模型清单和思考等级从 Pi 模型目录读取，不在客户端猜测能力；无推理能力的模型仅显示“关闭”。
- 卡片、节点详情和模型选择器在模型名称旁统一以 K/M 格式显示上下文窗口容量，便于结合路径上下文圆环判断可用空间；容量不是本轮输出长度上限。
- 新节点优先继承选中节点配置，根节点使用当前默认配置。每次运行配置保存在对应节点，不受输入区后续选择影响；编辑指令时可显式修改该节点的下一次运行配置。
- 服务端校验模型存在、凭证可用、思考强度受支持。未配置的真实模型在选择器中标明不可用。
- API 凭证通过服务端环境变量配置；前端只接收配置状态和变量名，不读取或保存密钥。
- 演示模型必须持续显示“演示”，其回答和统计不得伪装成真实模型结果；即使绑定工作目录，也不授予演示模型本地或联网工具。

## 6. 本地工作目录与编码审批（P0）

### 6.1 工作目录

- 新建探索只填写主题和背景，沿用系统生成且不可修改的 UUID 作为空间 ID；现有探索也使用原有 ID。未绑定本地项目时，默认使用 `<PANEL_DATA_DIR>/workspaces/<空间 ID>/`（默认 `.panel/workspaces/<空间 ID>/`），在首次真实模型任务时创建。临时目录在重启后保留，不自动清理；演示模型不创建临时目录，也不注册本地或联网工具。
- 根节点详情展示可选中复制的空间 ID、当前有效目录的绝对路径，以及「临时目录」或「本地项目」标记；长路径在窄屏可换行。工作目录可从根节点卡片打开弹窗，或在根节点详情选择、确认、更换本地项目，亦可清除自选目录并确认恢复临时目录。两个入口共用目录草稿与保存逻辑，关闭弹窗后可在详情继续确认或取消修改。目录草稿未保存时禁止从根节点发送任务，支持取消修改恢复已保存值。
- 目录选择器浏览本机服务可访问的文件夹，也允许输入绝对路径或 `~/` 路径。服务端检查目录存在、可访问并保存解析符号链接后的真实路径。
- `workingDirectory` 仅保存用户选择的本地项目路径；服务端快照提供只读 `temporaryDirectory`，有效目录为前者或后者。每个真实模型节点提交时保存有效目录快照。切换目录只影响后续任务，不自动迁移或删除任何文件，历史节点目录快照保持不变。有运行或排队任务时禁止变更该探索的目录。
- 不同空间的默认目录独立，同一空间各分支共享文件。临时目录与自选目录使用相同的工具、审批、路径校验和调度规则；临时目录不构成系统沙箱。
- 启动编码任务前再次验证目录。目录已失效或实际路径发生变化时明确失败，不自动切换到其他位置。

### 6.2 编码工具与执行边界

- 真实模型在临时目录和自选目录均直接复用 `pi/packages/agent/src/harness/tools/` 中的 `read`、`write`、`edit`、`bash` 工厂和 `NodeExecutionEnv`，适配至现有 Pi Agent，不复制工具实现或修改 Pi 子模块。
- `read` 支持按行读取；`write` 创建或覆盖文件；`edit` 使用 `edits: [{ oldText, newText }]` 精确替换原文；`bash` 在所选目录运行代码、测试、构建等命令。
- 文件工具校验真实路径，拒绝 `../`、外部符号链接和悬空符号链接绕过工作目录边界；新文件路径也检查已存在的父目录。
- 命令默认超时 120 秒，上限 600 秒，支持独立取消及终止进程组。保留 Pi 的输出截断：最多最后 2,000 行或 50 KB，超出部分写入临时日志。
- 本地 Shell 使用服务进程的本机权限，**不提供操作系统沙箱**；工作目录只是命令起始位置，不限制命令访问其他目录或网络。根节点目录设置与工作台应明确显示此边界。
- Shell 以明确的基础环境变量白名单启动，强制关闭服务端环境继承；模型凭据、未知应用密钥、代理/SSH agent 和启动注入变量不自动传给子进程。此限制不阻止命令主动读取本机配置文件。
- 文件分支隔离、自动回滚、独立 Git worktree 和容器均不属于本次实现；不得让用户误认为切换对话分支会切换文件版本。

### 6.3 审批模式与工具记录

- 默认模式为 `ask`（请求批准）：`read` 自动执行；`write`、`edit`、`bash`、`web_search`、`web_fetch` 每次执行前停下来等待批准，显示对应参数，并提供批准和拒绝操作。
- `auto`（自动审批）将每次本地和联网工具调用交给单独配置的安全模型。必须显式选择可用的真实模型，不能使用演示模型，也不默认复用执行模型。
- 安全审核是独立、无工具权限的单轮模型调用，输入包括用户目标、祖先问答、本轮之前的工具记录和本次完整参数。将这些内容视为待审数据，防止其中的指令覆盖审核规则；无法确认授权或风险时拒绝。严格要求结构化的批准/拒绝结论和理由，只有明确批准才执行。调用安全模型产生额外用量。
- 拒绝、配置缺失、不可用、60 秒超时、格式错误、上下文超限或网络错误均转为人工审批并展示原因，绝不默认放行。人工可以批准该次操作或拒绝；历史的直接自动放行记录必须明确标注旧版行为，不伪装成模型审核。
- 切换模式或安全模型不停止已派发执行的工具，已等待人工批准的调用保留原流程；审核进行中若设置发生变化，旧审核结果不得自动授权执行，转为人工确认。已经签发但尚未派发的授权失效，执行入口返回明确错误，需重新发起调用和审批。
- 服务端控制审批，不允许客户端仅改变显示状态就执行工具；一次批准只对应指定节点的指定工具调用，重复或过期审批返回明确错误。
- 批准后签发 30 秒有效、仅供单次执行的内存授权，绑定探索、节点、工具调用 ID、工具名、完整参数、工作目录、审批模式及安全模型配置版本。最终执行入口匹配并原子消费授权，消费记录保存后再次检查设置、有效期和取消状态再派发工具。变化、重放或保存失败均不执行。持久化授权摘要和策略版本用于审计，不得在重启后恢复执行权限；此机制不包含脚本/外部文件快照或操作系统隔离。
- 工具记录包括调用 ID、工具名、参数、状态、输出或错误、审批决定和时间，以及安全模型 ID、审核结论与理由。状态包括 `reviewing`、`awaiting_approval`、`running`、`completed`、`failed`、`denied`、`cancelled`，通过持久化和 SSE 同步；取消和重启会中断审核，迟到的批准不得执行工具。
- 单个节点最多进行 40 次模型回复，达到上限明确停止并保留工具记录及已完成的文件修改。界面的单次工具输出保留末尾最多 20,000 个字符；成功节点保留完整 Pi 工具消息用于后续上下文和 JSON 导出。
- 拒绝操作不产生该工具的文件或命令效果，并向 Agent 返回拒绝结果；后续调用仍按当前模式审批。
- 取消节点时结束其待审批操作和运行中工具；刷新后仍能查看记录并处理有效审批。服务重启后待审批和运行中记录标记中断，不自动批准或重放。

### 6.4 网页搜索与网页、PDF 读取

- 通过 Panel 适配层复用 [pi-web-access](https://github.com/nicobailon/pi-web-access) `0.29.0` 的 Exa 搜索和网页、PDF 文本提取，保持 `web_search` 和 `web_fetch` 工具名，无需选择本地项目；演示模型不注册工具。本次不加载插件其他工具或提供通用 Pi 扩展加载能力。
- `web_search` 接受查询、结果数和时间范围，返回搜索结果和来源网址；默认使用无需密钥的 Exa MCP，服务端可选配置 `EXA_API_KEY` 使用 Exa API。设置页显示当前模式和可选密钥的配置说明，不暴露或编辑密钥。无密钥不代表离线可用，搜索服务失败时必须明确报错，不伪造结果。
- `web_fetch` 接受公开 HTTP(S) 网址，提取可阅读的 HTML、文本或 PDF 内容，无需搜索密钥。不执行网页 JavaScript，不读取登录态，不提供浏览器自动化。
- PDF 使用本地 `unpdf` 提取文字，不对扫描图片进行 OCR，也不将原始 PDF 保存到工作目录；下载原文件仍需通过批准后的 `bash`，保存到当前空间临时目录或本地项目。
- 联网请求必须经过现有审批和单次执行授权；人工批准前或安全模型明确批准前不得请求搜索供应商或目标网页。审批界面说明查询会发送给搜索供应商、网页内容会交给对话模型。
- 服务限制请求时长、响应大小，校验网址、DNS 解析及每次重定向，禁止本机、内网和其他非公开地址；不使用浏览器 Cookie 或向目标网页传递服务端凭据。独立工具的网络约束不构成本机 Shell 沙箱。
- 将网页和搜索结果视为外部资料，不能覆盖工具权限与审批规则。工具记录保留查询、网址、结果与来源，界面只将有效 HTTP(S) 来源渲染为可点击链接；刷新和导出后可追溯。
- 未绑定本地项目的真实模型节点使用空间临时目录，保存有效目录、审批快照和工具记录，参与全局并发限制及目录锁调度。

### 6.5 文件更新与 Git 快照

- 每次获准执行的 `write`、`edit`、`bash` 操作前后比较有效工作目录，实际存在新增、修改或删除时保存一条独立 Git 快照并关联空间、节点 ID、节点运行版本、工具调用 ID、目录、时间及文件清单。只读命令、未改变内容的写入、未获批准的操作不生成更新记录；失败或取消前已经产生的文件变更仍保存快照。
- 快照保存在 `<PANEL_DATA_DIR>/git-snapshots/` 中，按空间和真实目录隔离，不修改项目原有 Git 历史、暂存区或配置，也不执行项目 Git hooks 或 clean filters。目录无需原先初始化 Git，但运行服务的机器需提供 Git。
- 按目录中的 `.gitignore` 规则记录可跟踪文件，排除 `.git`、`node_modules` 和嵌套的 Panel 数据目录；符号链接只记录链接本身，不跟随到目录外。工作目录外的 Shell 修改、忽略文件以及命令执行过程中已被再次覆盖的中间状态不在快照范围内。若外部程序同时修改文件，记录只表示该操作期间检测到的变化。
- 快照失败以单独错误记录显示，不将已执行的文件操作误报为未执行，也不自动重试工具。执行前持久化快照基线，服务中断后尝试补存实际变化并标记为恢复记录，绝不重放工具。扫描超时或容量超限明确报错。
- 记录独立于节点保存：重新生成保留各版本记录，删除卡片后保留快照且禁止跳转到不存在的节点。历史操作不能补建过去的文件版本；此功能不提供自动回滚或切换分支文件版本。

## 7. 并行执行与恢复（P0）

每个执行节点创建独立 Pi Agent，拥有独立消息数组、取消信号和配置。可在 A 分支运行时提交 B 分支；实际启动受全局并发上限和有效目录冲突约束。

- 状态机：`queued → running → completed | failed | cancelled`。
- 同时最多运行 3 个节点；同一父节点可提交多个不同子节点。同一真实目录或互相嵌套目录的编码节点串行运行，不同目录可并行。
- 调度按提交顺序选取当前可运行的任务；被目录占用阻塞的任务等待，互不冲突的后续任务可先运行。临时目录同样参与目录锁调度，同空间真实模型任务串行；演示模型不占用目录锁。
- 每个节点独立流式更新，切换选中节点不应停止其他分支。
- 单节点取消只影响该节点；排队节点也可取消。取消不撤销已完成的文件修改或命令效果。
- 失败保留问题、配置、部分回答和可理解的错误；“新分支重试”创建兄弟节点，“编辑指令”在原节点重新生成，后代按上下文过期规则处理。
- 浏览器刷新或断线后通过快照重新同步，后台任务继续运行。
- 服务重启时将未结束任务标记失败并说明“运行被服务重启中断”，不悄悄重复付费调用。
- 每次创建请求使用幂等请求 ID，网络重试不应导致重复运行。

## 8. 保存、检索与导出（P0）

- 多探索空间，本地服务端持久化；记录节点、消息、运行结果、上下文过期标记、拖拽坐标、工作目录、审批模式和工具记录。节点重新生成和子树删除通过快照与 SSE 同步。
- 采用串行写入和原子替换，避免并行节点互相覆盖；保存失败必须可见。
- 搜索当前图的问题和回答，选择结果定位节点。
- JSON 导出保留整张图和运行配置；Markdown 导出选中路径，便于复用。
- 视口偏好保存在本地浏览器；后端数据目录不纳入版本控制。

## 9. 本期边界

v0.1 本次扩展包含节点编辑后重新生成与子树删除、工作目录选择、文件读取与修改、Shell 执行、网页搜索与读取、审批切换和工具记录。不包含账号系统、多人协作、云同步、公开分享、原生桌面壳、附件、多父节点合并、自动研究规划、向量检索、独立分支文件系统或容器沙箱。

真实模型在空间临时目录或自选本地项目中均启用编码能力及已配置的联网工具；演示模型保持预设对话，不创建临时目录。网页读取不等同于完整浏览器。后续再增加隔离执行环境与分支文件版本管理。

## 10. 技术方案

| 层       | 选择                                  | 职责                                            |
| -------- | ------------------------------------- | ----------------------------------------------- |
| Web      | React + TypeScript + Vite             | 工作台布局、节点详情、表单、状态同步            |
| 图编辑   | React Flow                            | 节点、边、拖拽、缩放、小地图                    |
| 本地服务 | Node.js + TypeScript                  | 校验、图 CRUD、任务队列、SSE、持久化            |
| Agent    | 当前 checkout 的 Pi Agent + Pi AI     | 多模型、思考强度、流式消息、取消                |
| 编码工具 | Pi harness 工厂 + NodeExecutionEnv    | 文件操作、命令执行、取消与输出截断              |
| 联网工具 | pi-web-access 0.29.0 + Panel 工具适配 | Exa 搜索、网页/PDF 文本提取、来源记录与网络边界 |
| 存储     | 本地 JSON + 原子替换                  | 单用户首版，后续可迁移 SQLite                   |
| 测试     | Node test runner + 浏览器验收         | 分支隔离、并行、取消、重启、幂等与交互          |

Pi 源码作为独立依赖保留在 `pi/`，工作台代码置于目录根层的 `src/`、`server/`、`shared/`，便于单独演进和升级 Pi。

API 概览：

| 接口                                                       | 职责                                                                                         |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `GET /api/state`、`GET /api/events`                        | 获取快照与 SSE 更新，含工具和审批状态                                                        |
| `GET /api/models`                                          | 模型目录与连接状态                                                                           |
| `GET /api/capabilities`                                    | 网页/PDF 读取能力、Exa MCP/API 模式、可选密钥变量名及插件版本；不返回密钥值                  |
| `GET /api/directories?path=...`                            | 返回已验证目录、父目录和可浏览子目录                                                         |
| `POST /api/workspaces`                                     | 创建探索，接受 `workingDirectory`、`approvalMode` 和 `safetyModel`；自动审批必须选择安全模型 |
| `PATCH /api/workspaces/:id`                                | 更新目录、审批模式或安全模型；`safetyModel` 可设为 `null` 清除，自动审批模式下必须有效       |
| `POST /api/workspaces/:id/nodes`                           | 创建对话或编码节点                                                                           |
| `POST /api/workspaces/:id/nodes/:nodeId/regenerate`        | 接收新指令、模型配置、请求 ID 和预期 revision，在原节点重新生成；后代标记为上下文失效        |
| `DELETE /api/workspaces/:id/nodes/:nodeId`                 | 核对预期 revision 与确认的节点 ID 集合，删除节点及其子树                                     |
| `PATCH /api/workspaces/:id/nodes/:nodeId`                  | 仅修改节点坐标                                                                               |
| `POST /api/workspaces/:id/nodes/:nodeId/approvals/:toolId` | 提交 `{ decision: "approve" \| "deny", expectedRevision }`，仅处理对应节点版本的一次有效审批 |
| `POST /api/workspaces/:id/nodes/:nodeId/cancel`            | 取消节点及待审批或执行中的工具                                                               |
| `GET /api/workspaces/:id/export`                           | 导出完整探索或选中路径                                                                       |

服务默认绑定 loopback，仅用于本机；变更请求校验 Origin 和 JSON Content-Type，不开放跨域。API 不返回任何密钥。

## 11. 验收标准

1. 从示例或新建探索进入画布，节点与连线正确显示，拖拽位置刷新后仍在。
2. 从任意已完成的祖先节点新建分支，原分支保留；服务端测试证明兄弟与后代内容不进入上下文。
3. 在使用互不冲突目录的探索中同时发起至少两个真实模型运行，二者均实时更新；取消一个，另一个正常完成。同空间分支可同时提交，并按共享目录规则排队执行。
4. 每个新节点可以单独设置模型/思考强度，详情显示该次运行的真实配置。
5. 真实模型未配置时给出明确配置指引，不伪造成功；演示模式可完整演练上述流程。
6. 上下文页展示实际父链；“新分支重试”创建兄弟节点并保留原内容，“编辑指令”在原节点重新生成且保留 ID、父节点及画布位置，旧本轮消息不进入新运行上下文。
7. 重复提交相同请求 ID 只创建一个节点；队列、错误、取消和服务重启均可恢复为明确状态。
8. 多个探索的内容相互隔离，搜索可定位节点，JSON 和 Markdown 可导出。
9. TypeScript 检查及核心行为测试通过；在浏览器验证主流程和至少一种较窄窗口。
10. 新建与现有探索均可通过根节点卡片或详情选择有效目录，或清除自选目录并恢复临时目录，两处状态同步且刷新后保留；根详情显示空间 ID、有效目录和目录类型，窄屏长路径可读；无效目录明确报错，有活动任务时禁止更换目录。
11. 使用临时目录验证实际读取、写入、精确编辑、运行代码、命令失败、超时、取消和输出截断；目录外路径和符号链接不能绕过文件工具边界。
12. 请求批准模式下，读操作直接执行，写入、编辑和命令在批准前不产生效果；批准、拒绝、取消、刷新和重启均留下明确状态。
13. 自动审批必须调用所配置的安全模型，批准前无文件或命令效果；拒绝、审核异常、无配置均转人工。切换模式不放行已等待批准的调用；审核中取消、重启或更换设置后，旧结果不得自动执行。
14. 同目录、符号链接对应的同一目录及父子目录编码任务串行运行；互不重叠的目录可并行，仍遵守全局 3 个任务上限。
15. 界面明确说明本机 Shell 非沙箱、分支共享文件、取消不回滚；演示模型即使绑定目录也不执行工具。自动化测试与浏览器验收不能替代真实供应商端到端验证，未经实际调用不得宣称已经验证远程模型。
16. 浅色、深色和跟随系统均可切换；默认及跟随系统模式响应系统外观变化，手动模式不受系统变化影响，刷新后保留选择。画布、小地图、详情和弹窗主题一致，窄屏与收起主题区后仍能操作主题选择。
17. 未绑定本地项目的真实模型可使用网页/PDF 读取及默认无需密钥的 Exa MCP 搜索，并可通过批准后的 `bash` 将文件下载到空间临时目录；可选密钥启用 Exa API，设置页显示当前模式。联网操作在批准前不发送请求，拒绝或取消后不执行；来源链接随记录保存。PDF 提取不将原文件写入工作目录。
18. 联网工具拒绝非 HTTP(S)、本机与内网地址，并验证 DNS、重定向、超时、响应大小和取消；不能通过返回内容改变审批规则。未实际调用搜索供应商时不得宣称已验证真实搜索服务。
19. 非根节点编辑弹窗预填问题与模型配置；重跑后保留后代并标记上下文过期。过期节点不可分支，须从有效父路径逐个重跑；刷新后标记保留，兄弟分支不受影响。
20. 删除确认展示目标与后代数量，实际删除范围与提示一致，根节点不可删除。目标或后代有运行、排队任务时禁止编辑和删除；操作不回滚文件或命令效果。
21. 新旧空间未绑定本地项目时，首次真实模型任务创建以固定空间 ID 命名的临时目录，四项本地工具与审批正常生效；同空间任务串行，不同临时目录可并行。目录刷新及重启后保持一致，文件不自动清理；切换本地项目再恢复临时目录不迁移或删除文件，历史任务保留执行目录快照。演示模型不创建临时目录。

22. 左下角可执行自动布局；右上角 Git 记录可收起、滚动查看并定位对应卡片。实际写入、编辑及 Shell 增删改生成真实 Git 快照，重复内容/只读/拒绝不记；失败或取消后的部分修改可追溯。刷新、重新生成、删除节点及服务重启后记录保持正确，项目原有 HEAD 与暂存区不变。
