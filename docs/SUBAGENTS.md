# Subagents 子代理协作

Panel 接入 [nicobailon/pi-subagents](https://github.com/nicobailon/pi-subagents) `0.73.1`，每张卡片运行版本通过独立持久化宿主加载完整原生扩展。前台、后台、工作流、控制、角色管理、任务目标和调度使用原生接口；本地 Pi 子会话使用 Panel 的模型连接及审批。

## 使用

- **自动委派**：主模型可调用 `subagent`，通过 `action: "list"` 发现角色，然后按任务选择角色。
- **明确要求协作**：输入框 `@` 菜单选择 **Subagents**，本轮会先开启能力并要求主模型委派。开启记录和实际子代理分开显示。
- **长程任务**：选择 `@Subagents` 或模型实际执行已批准的 `subagents_enable` / `subagent` 后，本卡片自动进入长程模式，主代理可超过普通任务的 40 次模型回复限制；后台子代理唤醒主代理继续汇总时保持该模式。仅提及子代理、继承其他卡片的委派历史或拒绝自动委派不会触发；审批、用户停止和模型错误仍按原流程处理。新卡片独立选择模式。
- **查看结果**：卡片头像打开右侧 **Subagents** 子页；工作流单独显示为任务编排，不计入代理人数；默认打开实际子代理。查看各代理的任务、模型、工具、回答、用量及审批；思考和长任务默认折叠，正文支持复制与 Markdown 下载；原生验收报告呈现为交付说明、文件清单与注意事项，原始输出仍完整保留。
- **查看角色**：「模型连接」设置中的 **Subagents → 原生角色** 显示当前探索工作目录发现的配置，编辑文件后可重新读取；下一次调用也会重新发现。
- **控制**：子代理页用于查看分工、进度、结果和处理必要审批，不提供直接追加指令的输入框；任务指令统一交给主代理，由主代理使用原生工具引导、追加或恢复子任务。右侧仍保留暂停、停止、转入后台的运行操作。希望以后继续时用 `interrupt`；原生 `stop` 是终止。
- **管理与诊断**：日常页面不展示原生 JSON 参数、操作返回原文或后台通知。角色 CRUD/refine、工作流、missions/goals、计划任务、watchdog 等底层接口继续可用，日志保留在任务记录中；需要用户确认、输入或批准的事项直接展示。
- **工具记录**：主代理对话列表只展示主代理自己的调用（包括委派调用）；子代理的调用和计数保留在各自详情中。全局待审批入口显示来源代理、工具和目标，可以原地查看完整参数及审核理由、批准或拒绝，也可定位到所属代理详情；切换卡片不改变审批所属任务。
- **后台**：父卡片完成后后台子代理继续运行，审批、结果和通知保留在原卡片。完成通知会唤醒同一卡片里的主代理继续汇总；父模型仍在运行时先暂存通知。子页可查看执行进度和结果。
- **重启**：服务关闭会中断子代理，保留会话供 `resume` 恢复；普通未完成任务不自动重放。已明确创建的持久化计划随服务启动恢复，错过的触发按原生 catchUp 配置处理。导入只保留历史，不激活来源机器上的运行或计划。

子代理使用探索的实际工作目录。`context:"fresh"` 使用独立上下文；`context:"fork"` 从持久化父会话继承当时已有的消息和工具结果。宿主在委派前同步父会话，恢复使用插件保存的子会话。

恢复执行保留独立的原生 run ID、审批身份和工具审计；只有明确恢复关系且会话文件一致的执行才归并到原子代理页面。原任务、各次执行的工具和输出按执行时间保留，恢复处显示「主代理恢复任务」和追加任务。头像及人数按独立会话统计；新会话保持独立页面。旧记录可根据原生恢复提示中的 Original run 与同一会话文件识别，不能仅凭角色或任务文本相似归并。

本地子代理的工具执行事件在宿主实际授权派发后才交给原生超时计时器；等待自动审核、人工批准及文件锁不消耗工具执行时间。原生角色或调用配置的工具超时仍生效，整次运行的总期限和预算保持原生语义。自动审核和人工等待均显示「等待审批」，执行超时显示「执行超时」，主动停止显示「已停止」，暂停显示「已暂停」。

原生产物使用 `artifactDir: "project"`，放在实际工作目录的 `.pi/subagents/artifacts/`；受管 worktree 的原生输出路径随子代理实际目录解析。恢复默认显式复用已记录的输出路径，模型明确提供新 output 时遵循该参数。旧记录的宿主 `subagent-artifacts` 输出目标恢复时迁移到工作目录内并保留原任务 ID 和文件名；任意其他目录外目标不自动放宽。会话与角色配置仍保存在 Panel 数据目录。

## 原生角色配置

复用插件发现和覆盖规则，继续发现 `~/.pi/agent/agents/`（或 `PI_CODING_AGENT_DIR`）及项目 `.pi/agents/`。在 Panel 创建的用户角色和覆盖设置保存在 `PANEL_DATA_DIR/subagents/agent/`；每张卡片有独立运行配置、会话和计划目录，共享角色定义。旧目录、嵌套目录、别名和 `subagents.agentOverrides` 由原生发现器处理，无效配置明确报错。

Panel 已移除 `claude-code`、`claude-code-writer`、`codex-exec`、`codex-exec-writer`、`cursor-agent`、`cursor-agent-writer` 六个外部 CLI 角色。角色列表、模型发现与执行使用同一排除规则，重新安装依赖不会使它们恢复；桌面包也不包含这些角色定义。当前保留七个内置角色：`scout`、`worker`、`reviewer`、`oracle`、`delegate`、`researcher`、`evidence-auditor`。

例如项目 `.pi/agents/security-reviewer.md`：

```markdown
---
name: security-reviewer
description: Review changes for security defects
aliases: security
tools: read, grep, find, ls
model: openai/gpt-5
thinking: high
systemPromptMode: replace
inheritProjectContext: true
inheritSkills: true
---

Review the assigned changes. Report concrete defects with file locations and evidence.
```

模型名称应改为 Panel 已配置连接中的模型；省略 `model` 时继承本轮模型连接快照，省略思考设置时使用本轮思考强度。配置了模型或思考强度就优先采用角色配置，不强制覆盖成主模型设置。

保留原生 `tools`、`excludeTools`、`skills`、`skillPath`、`extensions`、`subagentOnlyExtensions`、提示词 append/replace、项目/全局指令及技能目录继承。原生会话运行工具权限和工具预算钩子，处理角色超时、验收要求、结构化输出、默认读取文件和输出路径。命名但找不到的技能或工具会明确失败，不缩小白名单后继续运行。

`tools` 省略时按 Pi 默认工具及已加载扩展处理，空数组关闭工具。scout、worker、reviewer、oracle 等使用插件提供的真实定义；例如 scout 原生允许 `bash`、`write`，reviewer 使用 `watchdog_diff`，不能把角色名称当成权限边界。

Panel 默认提供 `pi-web-access@0.34.0` 的研究工具：`web_search`、`fetch_content`、`get_search_content`、`source_check`，`researcher` 和 `evidence-auditor` 无需另配扩展即可使用。工具在独立子进程内加载插件实际定义和内容缓存；明确加载的自定义扩展仍优先保留自己的同名工具定义。

- `web_search` 接受原生 `query/queries`、`numResults`、`recencyFilter`、`domainFilter`、`includeContent`、`workflow: "none"`。`query` 与 `queries` 分别用于单条和批量搜索，进入同一原生执行器，均返回缓存 ID；只接受当前工具定义中的参数。
- `fetch_content` 接受公开 HTTP(S) `url/urls` 和 `readable/raw` 模式，原文通过 `responseId` 留在当前代理缓存。PDF 私有提取文件转换为可分页的文本，不向模型暴露临时文件链接。
- `get_search_content` 使用插件原生分页和 `findText/findMode` 检索；不发起网络请求。每个主代理/子代理拥有独立缓存，ID 不跨代理共享，当前执行完成或取消后清理。跨代理交接使用来源 URL 和必要原文。
- `source_check` 保留插件的证据结构、引用片段与内容哈希；不会自动认定某论断为真，仍需模型核验。附带原文获取在本次批准的调用内完成。
- `@web_search` 使用原生 `query` 启动方式。主代理和子代理只注册上述四个联网工具；长搜索结果、网页及 PDF 内容通过 `get_search_content` 继续分页读取。

当前联网后端继续使用既有 Exa MCP / `EXA_API_KEY`。研究工具不开放交互 curator、额外模型摘要、浏览器 Cookie、本地视频、调用方代理或新搜索提供者；不支持的参数显式报错。主代理及默认研究子代理的补充提示词与这些实际接口对齐，原生角色提示词和工具白名单保留。

## Panel 适配

### 输出预算、续写与交接

Panel 主代理和本地 Pi 子代理的回答请求默认以当前模型的 `contextWindow` 作为输出上限，不再使用固定 8192、16384 或上下文四分之一的回答上限。上下文设置覆盖同样生效。Pi 在发送实际请求时仍扣除输入和安全余量；这项配置不改变服务端模型的真实生成能力。如果服务端在生成任何内容之前明确返回了更小的输出参数上限，本次运行采用该数值重试一次并复用，不能识别的限制明确报错，不猜测上限。

输出上限与上下文压缩预留分开计算：主代理继续预留至多 16384 tokens（小窗口按四分之一缩放），原生子代理保留 Pi 自动压缩和角色/项目设置。摘要请求使用独立的小预算，不预留整个模型窗口。自动压缩只改变模型输入，原始历史、文件操作和检查点来源仍保留。

`length` 停止在当前任务中最多自动续写 3 次；重复输出或无新增内容时提前停止。截断的工具参数不执行，正常工具操作不重放。续写提示要求接着已有内容完成任务；原生交接包含前后各段，Pi 会话文件仍保留原始逐条消息。达到续写边界后明确标记“输出未完成”，并保留部分结果。输入上下文超限、服务端输出参数限制与输出未完成分别说明原因。

父代理与本地子代理的补充提示词要求将长任务拆成章节或独立小任务，允许写入时逐段生成文件，最终返回关键结论、证据、未完成项及真实路径。工具白名单和权限保持原有规则。

成功的 `subagent` / `subagent_status` 结果超过 16000 字符时，Panel 在模型输入投影中保存完整结果到工作目录 `.pi/subagents/handoffs/`，通过已有文件审批流程记录保存，再用独立、无工具的模型请求生成最多 2048 tokens 的交接摘要和文件引用。短结果、角色发现和指南不变；原生工作流内部的返回值、卡片及会话原文不改写。摘要请求最多读取 64000 字符；更长内容只概括首尾并明确标注覆盖不足，主代理可以 `read` 分段读取全文。保存被拒绝或失败时保留 inline 原文；摘要失败时返回文件引用及明确标注的原文节选，不冒充完整摘要。

本地原生前台、后台、脱离及嵌套 Pi 会话共用这些生成规则。远端及外部 CLI 的生成预算和续写仍由对应运行器控制；返回 Panel 的长结果可使用相同的交接投影。

### 重试与后台汇总

瞬时断流、限流及可恢复服务错误继续使用 Pi 原生自动重试（默认最多 3 次，初始退避 2 秒，受原生设置覆盖）。成功恢复后清除卡片里的中途错误；最终失败仍保留原因，不重新启动整个已执行的任务。

插件发出 `triggerTurn: true` 的后台完成或请求通知时，Panel 在同一卡片、同一运行版本上继续主代理，保留已有消息、工具和回答，追加汇总。主代理尚在运行时暂存并合并通知，待当前调用结束后处理；`triggerTurn: false` 的增量通知只记录，不触发额外模型轮次。工作流正常完成或最终失败都会交回主代理，由它说明结果及缺口。唤醒不重新执行原来的 `@` 工具准备，不增加用户授权；长通知同样使用经审批的文件与摘要交接，原文仍在记录中。

取消、删除或更换卡片版本后不接受旧通知；打开历史卡片及重启应用不会重放历史通知。后台任务需要 Panel 后端保持运行，停止应用不会在关机期间自动汇总。

### 执行与记录

- 本地 Pi 子会话内置及扩展工具经过所属卡片的审批和单次授权，调用 ID 按子代理隔离。父任务结束不使活跃子代理审批失效。
- 主、子代理共用探索的审批模式和安全模型。自动审核附带子代理身份、委派任务和各历史调用的来源；模型编写的分工只作审核背景，不增加用户授权。安全模型未批准或审核异常时仍转人工审批，不直接执行。
- 安全审核完整保留当前用户要求、已送达的追加消息、祖先用户要求及本次工具参数，默认不提供历史助手叙述。主会话及子代理共用历史总预算，最多 32,768 个估算 token，按审核模型剩余容量继续缩小；优先保留明确拒绝、当前命令引用的代码证据和同目标记录，再选最近记录（最多 12 条，相关代码证据单独优先选择）。历史嵌套任务、`edits`、长命令和宽／深数组对象递归精简并标明省略与内容指纹，本次参数不截断。相同动作、批准来源、结果和卡片／版本／目录／子代理范围的重复审批合并，保留次数及首末时间；拒绝、人工批准与自动审核不混并，原始审计记录保持完整。代码证据仅放一份，明确标记节选及未纳入的证据，不把无关搜索／网页正文带入审核。必要用户授权和本次动作超过模型容量，或明确拒绝无法完整纳入预算时转人工，不静默放行。指纹、历史批准次数和省略内容不能替代授权或完整代码审阅。
- 人工拒绝只拒绝当前调用，操作不执行、不消费授权；拒绝结果返回子代理，它可以继续其他已授权的工作、说明缺口或回报主代理，不自动停止整个子任务或其他并行代理。取消／停止仍是独立操作，拒绝不能通过换工具或重新委派绕过。
- 「批量同意」仅覆盖此卡片本轮、同一工作目录的同名工具，包含主代理及子代理；其他目录、工具、卡片和后续运行不继承，审批配置改变后失效。
- `read/write/edit/bash` 使用 Panel 执行器；`grep/find/ls` 使用 Pi 工具并限制搜索根目录。授权、文件锁和 Git 快照绑定子代理实际目录，包括受管 worktree。
- 原生全局技能可通过 `read` 读取已发现的技能目录。Panel 将工作目录外的这些只读操作记录为 `read_skill` 并单独审批；普通文件读写仍受工作目录边界限制。
- 配置的扩展是本地可执行代码，使用 Pi 原生扩展生命周期；它们注册的工具经过 Panel 审批。Panel 的文件路径限制适用于内置文件工具，并非扩展代码的操作系统沙箱。
- 委派本身可能写原生报告、创建工作树、执行验收命令、修改配置或启动外部运行器，因此先审核完整委派参数。这些插件直接管理的效果属于整体委派授权，内部制品不伪装成子代理 `write` 调用。输出位置、保留和验收遵循原生协议。
- 运行、工具、通知和会话位置保存在卡片中。父任务完成时汇总已有子代理用量；后台唤醒后的汇总只累加尚未计入的子代理用量，各子代理详情保留自身用量。

`tasks` 简写仍最多 8 个并默认等待结果；完整工作流使用 `workflowScript`、`workflowScriptPath` 或命名 `workflow`。并发数映射到原生 `globalConcurrencyLimit`（一棵运行树，包含嵌套），默认 4，可设 1–8。多个后台根任务另受 `maxActiveAsyncRunsPerSession` 管理。默认深度 3、每棵树最多 64 次启动。设置页仅显示并发数和原生角色；后台、嵌套、启动数、超时与预算等高级选项不在界面展示，已有设置继续生效。调整或恢复并发数不会重置高级配置。

## 支持范围

- **工作流**：原生脚本串联、并行、条件分派、命名资源、持久化 missions/goals、worktree、预算、watchdog 和计划管理均由扩展执行。用 `subagent({action:"guide",topic:"tool-reference"})` 查询完整参数。
- **提供者扩展**：宿主加载用户全局扩展，使其可以注册命名工作流和外部任务提供者；避免重复启动 ambient `pi-subagents`。项目扩展仍由各子代理的原生配置决定是否加载。
- **监督者**：`subagent_supervisor` 提供 pending/status/reply。子页 JSON 使用 `"tool":"subagent_supervisor"` 选择该工具。
- **外部 CLI**：支持自定义 `runner.type:external-cli` 及上游适配器；需要相应程序与认证。六个已卸载角色不会恢复。外部 CLI 内部工具由其环境管理，Panel 审核整个委派。
- **远端与交互模式**：接通上游 Herdr 放置及 inspector/project 接口，需要对应服务、保存的 machine 和远端环境。通用命令 runner 仍遵守原生“仅本地后台”的限制；未配置时保留明确错误，不降级成本地 Pi。
- **MCP**：后台按原生角色配置加载扩展及 `mcpDirectTools`。保留用户全局 skills、上下文和扩展入口；MCP 服务和工具提供者需自行配置。
- **界面**：管理与控制通过 Panel 子页操作；终端专用全屏 TUI 和快捷键布局不在网页绘制，Herdr 交互终端由其界面承载。
- **生命周期**：后台脱离父模型调用，仍需要 Panel 后端和模型通道运行。关闭应用不是常驻服务；会话恢复与计划重启不意味着电脑关机期间仍执行。
- **其他边界**：电脑控制不传给子代理；本地 Pi 继续使用 bash，未增加 powershell。外部/远端内部变更不属于本机逐工具快照。

## 维护

`nicobailon-engine.ts` 集中引用固定版本入口。`subagent-host.ts` 管理生命周期与私有 Unix socket，`subagent-host-worker.ts` 加载完整扩展，`subagent-host-factory.ts` 同时供前台和脱离运行器使用，`subagent-session.ts` 适配模型与工具。原生全局 factory 限于独立宿主，不在多个 Panel 卡片之间共享。

桌面打包保留插件角色文件、SDK 资源和可供用户扩展解析的 Pi 模块。升级需要运行原生角色集成测试、审批/取消测试、UI 测试及桌面自带 Node 的真实子会话冒烟测试。

已通过本地模拟模型验证前台、后台、嵌套、重启续跑、外部 CLI、审批和联网。真实远端机器及交互 CLI 需在对应环境验证。打包后台/嵌套冒烟：`PANEL_TEST_APP=... node scripts/test-native-host.mjs`。
