## 安装与启动

需要 Node.js ≥ 22.19。`pi/` 以 Git 子模块固定到已验证的上游 `v0.99.1`，克隆时一并拉取：

```bash
git clone --recurse-submodules https://github.com/H0ypothesis/panel.git
cd panel
npm ci --ignore-scripts
npm run setup:pi
npm run dev
```

如果已克隆但没有初始化子模块，先运行 `git submodule update --init --recursive`。依赖升级或修改依赖时使用 `npm install --ignore-scripts`。

打开 <http://127.0.0.1:4317>。首次运行或升级 Pi 后执行一次 `setup:pi`，从随 npm 安装的同版本官方发布包复制模型目录；初始化、随后启动和演示模式均可离线使用，不访问 Vercel 或其他远程模型目录。

`@panel/pi-model-data` 是固定到 `@earendil-works/pi-ai@0.99.1` 的 npm 别名，仅用于取得官方元数据；Agent 仍使用 `pi/` 源码。安装入口核对源码与发布包版本，并使用 Pi 自带校验器检查目录格式、供应商、模型标识和文件哈希，全部通过后再替换旧目录。失败保留旧数据。升级子模块时需同步此别名版本和锁文件；不再依赖实时生成器或 models.dev 的区域目录映射。

从 Pi 0.85.1 升级时，Panel 已将回合结束控制迁移到 `finishTurn`，保留普通任务 40 次回复上限、长程任务、工具预执行、取消与错误原因；导入导出同时保留新版消息的思考强度字段。

没有 API Key 也可体验对话分支工作流。默认提供 **Pi Demo 演示模型**和明确标注的示例探索。演示模型使用真实 Pi Agent 和 faux provider 流式执行预设回复，不是远程模型推理，不产生模型费用，也不会执行本地或联网工具。

## 数据与运行

数据保存于 `.panel/state.json`，写入串行化并通过原子重命名落盘；流式过程每秒保存，节点创建/结束立即保存。浏览器关闭不终止运行。服务重启将未结束节点标为失败，不自动重复模型请求。

开发模式只对前端热更新。修改 `server/` 或服务端使用的共享代码后，需等待当前任务结束并重启服务。发送带卡片引用的任务前，前端会确认后端已加载引用功能；旧版本服务会明确提示重启，并保留草稿，不会仅发送引用标题而丢失正文。

新建卡片和编辑卡片时，可在模型设置旁开启「长程任务」。普通任务最多执行 40 次模型回复；长程任务没有这项次数限制，直到模型完成、发生错误或用户停止。设置按卡片保存，编辑、重试和导入导出时保留，新卡片默认关闭。通过 `@电脑控制` 发起的任务自动启用长程模式；模型本轮实际执行已批准的 CUA 工具时也会自动启用。仅提及 CUA、引用历史轨迹或被拒绝的调用不会触发。长程模式不改变工具审批、窗口并发协调或上下文压缩规则。

可配置 `PORT`（默认 4317）、`PANEL_DATA_DIR`（默认 `.panel`）。服务只监听 `127.0.0.1`，设计用于本机单用户。不要对同一个数据目录同时启动多个服务实例。首版不提供账号或公开分享，工作目录、审批模式和工具记录随探索一起保存。

```bash
npm run check       # 前后端 TypeScript 检查
npm run test:setup  # 安装时的模型目录兼容与严格校验回归测试（无需联网）
npm run test:core   # 分支、审批、目录调度、本地与联网工具、取消、恢复、API 和 Pi 演示测试
npm run test:ui     # 前端逻辑、组件及对话切换/重试的 DOM 回归测试
npm run test:updater # App 更新包校验、失败恢复与更新提示交互
npm run build      # 生成前端发布文件
npm start          # 本地生产模式，仍需要 node_modules 与 pi/ 源码
```

## 电脑控制与 MCP

Panel 已直接接入官方 Cua Driver 0.30.4。运行 `npm run setup:cua` 安装经过哈希校验的项目内驱动，然后在「电脑控制」中连接并完成 macOS 权限授权。光标覆盖层默认开启；操作、审批、等待窗口以及截图都显示在对话工具卡中。当前模型需要支持图片。

如果提示「当前连接的 Panel 服务尚不支持电脑控制」，或 `/api/computer-use` 返回 404，说明当前连接的后端仍是旧版：

- 开发环境：等待正在运行的任务结束，停止原来的 `npm run dev` 进程，再从最新源码启动。只刷新页面不会重新加载后端代码。
- macOS 应用：按照[从源码构建](MACOS.md#从源码构建)生成新版 `Panel.app`，退出旧应用、替换已安装的应用后再打开。应用使用包内的独立后端；更新源码或在旧应用中「重启本地服务」不会更新它。

完成后打开「电脑控制」并刷新状态。驱动尚未安装会显示「待安装」，与旧后端缺少接口是两种情况。

输入框中的 `@` 菜单同时提供卡片引用和本轮工具选择。「联网搜索」会在发送后先以本轮输入执行搜索；「电脑控制」会先加载工具并发现应用，再交给模型定位目标。选择不会立即执行，发送后仍经过正常审批。工具选择随草稿、编辑、原地重试和导出保存，后续分支不会隐式继承。未连接真实模型、未安装 CUA 或模型不支持图片时会明确提示。

CUA 运行期间，右侧「电脑控制」旁可开启「CUA 接管」。开启后，本卡片本轮的查看、截图、后台滚动和浏览器指针移动免去逐次安全模型审核；点击、输入、快捷键、拖动、导航、启动应用和窗口变更仍走正常审核。显式前台滚动也继续审核。开关默认关闭，可随时关闭，不传给其他卡片、重试或下一轮，服务重启后重置；已经进入审核或等待批准的操作不受切换影响。免审由固定的工具及参数白名单判定，未知模式和额外字段不会放行；参数校验、观察要求、窗口锁和停止机制保持生效。

关闭接管会阻止后续免审派发，不会中断已经交给 CUA 执行的单次操作（包括正在等待其他电脑操作完成的调用）；如需中断当前运行，请使用卡片的停止按钮。

同一窗口或页面由一个运行独占，直到主动释放、切换目标或本轮结束；同一应用的不同窗口可并行，浏览器精确绑定后的不同标签页也可并行。窗口级操作会等待其所有页面释放，需要前台的操作会额外串行。不同 Panel 服务进程之间不共享锁，不能让多个服务同时控制同一桌面。详细安装、生命周期和上游协议见 [CUA.md](CUA.md)。

项目已预装 [pi-mcp-adapter](https://github.com/nicobailon/pi-mcp-adapter) `3.3.0`，版本固定在 `package.json` 和锁文件中，随 `npm ci --ignore-scripts` 安装，用于后续接入更多 MCP 服务。该版本对 `pi-ai` 的可选 peer 范围尚未包含 0.99.1，但实际只导入其类型；项目通过仅针对 3.3.0 的 override 复用当前 Pi，避免安装旧核心。已通过内存传输验证其 host-managed 入口的加载、初始化、工具发现、拒绝与批准调用、关闭；这不代表插件所有扩展功能或外部 MCP 服务已完成端到端验证。

Panel 直接创建 Pi Agent，CUA 使用专用桥接层衔接审批、目标锁、截图、取消和连接清理。通用 `pi-mcp-adapter` 尚未加载；添加 `.mcp.json` 或在 Pi CLI 中安装扩展不会自动为 Panel 启用任意 MCP 工具。macOS 打包会包含已安装的 CUA 驱动。

## 目录

```text
docs/PRD.md      产品需求文档
src/            React 工作台和图画布
shared/         对话图类型、路径与布局逻辑
server/         HTTP API、SSE、Pi 适配、队列与持久化
pi/             上游 Pi 源码子模块，固定版本，不修改其业务代码
```

当前自动化验证覆盖演示模型、临时目录中的实际文件读写与命令执行、审批和本地工作流；没有把这些检查当作真实供应商端到端验证。真实模型调用需要配置有效凭证。

详细验收范围见[产品需求](PRD.md)和[首版验收记录](VERIFICATION.md)。
